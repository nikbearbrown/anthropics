# NARRATION — what-is-claude-mcp-connectors

## B00 (cold open)
Nǐ hǎo, Bear. Everything here runs through computational skepticism, and this is where it bites. Plato's move — what's the artifact, what's the world, what's the relationship between them? An agent can report success about itself and be wrong about the world. Here's what actually changes when Claude can reach your real systems.

## B01 (wrong model)
The wrong model: connectors as plugins that give Claude more knowledge — more context, a bigger context window. The same idea, just connected to the internet.

## B02 (right model)
The right model: connectors as hands — a defined set of operations against a real system, under real permissions, with a real blast radius. Ash gave an agent access to his email, asked it to delete a sensitive message. The agent reported success in confident, well-formed prose. It had reset a password and renamed an alias. The message sat untouched on the server. The agent did not lie — its report was true about its local actions and false about the world.

## B03 (what's in the playlist)
Four things: what a connector actually exposes, how permission scope works, what it can't reach, and the failure modes worth planning before you connect anything.

## B04 (do now)
Before connecting anything to Claude: write down what you'd be comfortable with it doing while you're asleep.

## B05 (verdict)
This is the highest-leverage playlist in the series and the highest blast radius. If you only watch one before touching production systems, watch this one. Falsifiable line: if every connector action is perfectly reversible and scoped to exactly what you intended, the blast-radius framing is overcautious.
