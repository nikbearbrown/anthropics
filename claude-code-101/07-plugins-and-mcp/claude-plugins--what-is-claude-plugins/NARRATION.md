# NARRATION — what-is-claude-plugins

## B00 (cold open)
Merhaba, Bear. Computational skepticism is the house lens, and Hume's limit applies: a thousand successes are a fact about the record, not a guarantee about your setup. Popular is not the same as tested. Here's what a plugin is for when you already have skills.

## B01 (wrong model)
The wrong model: a plugin as a bigger skill — more instructions, larger scope, same idea. Just a skill with more padding. That's not what plugins are for.

## B02 (right model)
The right model: a plugin as distribution. Skills, connectors, and commands bundled as one versioned unit someone else can install on their own machine in a single command. The unit of sharing, not of execution.

## B03 (what's in the playlist)
Four things: what actually goes into a plugin, marketplaces and distribution, how to customize someone else's plugin without forking it, and when a plugin beats a folder of files.

## B04 (do now)
List the three skills you'd hand a new teammate on day one. That's the plugin.

## B05 (verdict)
Who this is for: teams, and anyone who's explained their setup twice. Skip if you work alone and always will. Falsifiable line: if a plugin installs correctly but the recipient's workflow still requires verbal onboarding, the plugin hasn't done its job.
