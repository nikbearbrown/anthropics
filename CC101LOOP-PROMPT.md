# CC101LOOP — build ONE Claude Code 101 reel, unattended

You are a fresh Claude Code session inside a shell loop (`cc101loop.sh`). Your job: turn ONE concept folder of `claude-code-101/` into ONE finished `cc-explainer` reel, then stop. The supervisor starts the next one. All state is on disk; if you crash, the next worker resumes from what you wrote.

## Read first (in this order — do not skip)
1. `$BRUTALIST_ART/skills/make/cc-explainer/SKILL.md` — the whole file. It carries LIAM LAW, TERMINAL-FIRST, REAL-SESSION, the spine (cold open → THE IDEA → DEFINITIONS → loop → CONDUCT → HUMAN → BVDT/BHTF/BOUT), the component contracts, and the kit gotchas (text blocks ≤ 44 chars, ledger rows ≤ 30, score steps ≤ 44, verdict 4 or 6 lines, `mascot: "off"` on full stacks, `CCPlainShell` for anything outside a session, never edit the sheet while `art run` is alive; status `tokens` strings WITHOUT a leading `↓` — the kit adds it).
2. `$EXEMPLAR/author_sheet.py`, `$EXEMPLAR/SESSION.md`, `$EXEMPLAR/FACTCHECK.md`, `$EXEMPLAR/BUILD-LOG.md` — a finished reel of this exact kind. Copy its `author_sheet.py` helpers (`B`, `R`, `writer`, `session`, the metadata block, the budget asserts) verbatim; only the beats and metadata strings change.
3. `$CONCEPT_DIR/beat_sheet.json` — the concept you are filming. Take its **idea**, its title's claim, and its Your-Turn intent. Do NOT reuse its beats, its card copy, or any statistic in it; those were never checked against a session.

## What you build
`$REEL_DIR/` (create it; slug `$SLUG`), containing: `SESSION.md`, `evidence/` (raw `--output-format stream-json --verbose` of every run, every file the runs produced, diffs), `author_sheet.py`, `beat_sheet.json`, `scenes.py` (docstring only), `FACTCHECK.md` (the `| # | Beat | Claim | Verdict | Source | Fix |` table with PASS/CORRECTED/EXEMPT and a `Status:` line; escape `|` inside cells as `\|`), `SHOTLIST.md`, `PROMPTS.md`, `SOURCES.md`, `CHECKS-REPORT.md`, `BUILD-PROMPT.md`, `BUILD-LOG.md`, `mp3/`, `media/`, and the master `$SLUG.mp4`.

## The method — the session is the film
1. **Design a real, checkable session** that shows the concept: a scratch git repo under `$REEL_DIR/scratch/` (small: a few files, tests on `unittest`, never pytest — it is not installed), one or more headless runs
   `claude -p "<what Liam typed>" --output-format stream-json --verbose --max-turns 16 --permission-mode acceptEdits --strict-mcp-config --allowedTools "Read,Write,Edit,Glob,Grep,Bash(ls:*),Bash(cat:*),Bash(python3:*),Bash(git:*),Bash(wc:*)" < /dev/null > evidence/turnN.jsonl`
   (add `--session-id <uuid>` on the first message and `--resume <uuid>` on later ones; a NEW `claude -p` is a fresh session — that is `/clear`). Slash commands work headless: `/init`, `/compact`, `/context`. Quote every flag value; never `git clean` between trials without copying evidence out first. Keep `python3`, not `python`, in the allow-list.
   If the concept's claim can be tested (a number, a "breaks when", a "costs N×"), **test it** and film what the receipts say — even when the claim fails. If the concept cannot be shown from a headless session at all (it needs the interactive UI: plan-mode cards, the IDE, rewind, the Chrome extension), build the film around what headless CAN show and say so in `BUILD-LOG.md`; if nothing can be shown, write `$CONCEPT_DIR/CC-BLOCKED.txt` with one line saying why and stop.
2. **Liam verifies with commands** after every run (wc, grep, git diff --stat, the tests). Paste them into `SESSION.md` verbatim with outputs. Every `CCSession` block in the sheet must trace to `SESSION.md`.
3. **Author** `author_sheet.py` on the exemplar's shape: B00 cold open (`CCSession`), `BIDEA` (`BrutalistHesitantWriter`, CC palette, one word reconsidered = the film's misconception, pace props from the exemplar), `BDEFS` (`CCDefinitions`, 2–5 jargon terms, one plain line each, for smart chat-window users), the loop beats (PROMPT/THINK/TOOLS/CHANGE/VERIFY — VERIFY is Liam's command, never Claude's ✓), a correction cycle, then CONDUCT (`CCBoondoggleScore`) and HUMAN (`CCHumanLedger`), then `BVDT` (`ClaudeVerdictArtifact`, exactly 4 lines, last line `FALSIFIABLE: …`), `BHTF` (`ClaudeComposerAsk`, greeting "Your turn.", topic "YOUR TURN · CLAUDE CODE 101"), `BOUT` (`ClaudeTitleOutro`, `handle:"@NikBearBrown"`, `subline:""`). `metadata.skill` = `cc-explainer`; Liam (`am_onyx`) on every beat; first-person, present tense, Teardown register; the cold open says "This is Liam, in for Bear."; BVDT starts "Let's recap with Claude."; BOUT is the exact title then "Liam, in for Bear." No datable numbers spoken (versions, model names, prices). Fix every budget warning the script prints before continuing.
4. **Voice**: `python3 $BRUTALIST_ART/runtime/scripts/generate_audio_kokoro.py $REEL_DIR` (all beats). After this, never run `author_sheet.py` inside `$REEL_DIR` again — regenerate to a temp dir and merge props, or the audio stamps are wiped.
5. **Paperwork**, then `python3 $BRUTALIST_ART/runtime/qc/factcheck_check.py $REEL_DIR` must print `clean`.
6. **Compile**: from `$BOOKS`, `./brutalist-art/art run <reel-relative-path>` then `./brutalist-art/art final <reel-relative-path>`. Read `_qc/REPORT.md` and `TYPECHECK.md` on any failure; fix at the source (shorter strings, `mascot:"off"`, 4 verdict lines), clear that beat's `shot.remotion.rendered` to `{"out":"","at":""}`, delete `media/<id>.mp4`, run again. Grab frames from `media/*.mp4` at 90 % with ffmpeg and look at the dense ones (session stacks, score, ledger) for clipping or overprint; fix and re-render those beats.
7. **Finish**: `BUILD-LOG.md` (what the session gave the film; every compile pass; what was corrected), then write `$CONCEPT_DIR/CC-BUILT.txt` containing the absolute path of `$REEL_DIR`. Update nothing else in `claude-code-101/INDEX.md`; the supervisor does that.

## Hard rules
- **Never publish. Never touch `books/youtube/TOPOST/`.** The master stays in `$REEL_DIR`.
- Never spend money beyond the Claude API calls of the session itself (no Higgsfield, no ElevenLabs — Kokoro only).
- Never edit the skill, the kit components, `Root.tsx`, or another reel. If the kit is missing something, film without it and log `MISSING:` in `BUILD-LOG.md`.
- Never name Bear's unpublished books or courses in narration.
- One reel per invocation. When the master exists and `CC-BUILT.txt` is written, stop.
