## Candidate 01 — Build a DCF Terminal Value Sensitivity Grid: Watch g Drive 60% of Value with Claude
- Source: corporate-finance-with-ai/chapters/04-capital-budgeting-at-the-firm-level.md
- Lane: BUILD (Claude Code)
- Hook: In a typical DCF, the terminal value accounts for 60–80% of total enterprise value. The terminal value is driven almost entirely by g, the perpetuity growth rate. A 0.5% shift in g can move the valuation by 20–30%. Can you see this dependence visually before you trust a single number?
- The artifact: A Python script that builds a DCF for a synthetic firm (FCFF projections, discount rate, terminal value via Gordon Growth), then generates a 2D sensitivity grid: WACC (rows) × g (columns), each cell showing enterprise value in $M. A Manim animation sweeps the cursor across the g-axis of the grid, showing the enterprise value moving dramatically while WACC changes cause smaller effects — visually confirming that g is the dominant driver.
- Prompt seed: `claude "Write a Python script that: (1) defines a 5-year FCFF forecast: [120, 135, 148, 160, 170] $M for a synthetic industrial firm; (2) computes enterprise value = PV of FCFFs + terminal value, where terminal value = FCFF_5 × (1+g) / (WACC - g); (3) generates a 7×7 sensitivity grid with WACC in [0.07, 0.075, 0.08, 0.085, 0.09, 0.095, 0.10] (rows) and g in [0.015, 0.02, 0.025, 0.03, 0.035, 0.04, 0.045] (columns); (4) prints the grid as a formatted table with column/row headers; (5) prints the ratio of terminal value to total enterprise value for the base case (WACC=0.085, g=0.025). No external libraries."`
- Read / check: Verify the terminal value formula uses FCFF_5 × (1+g) / (WACC - g), not FCFF_5 / (WACC - g). Confirm the base-case terminal value is approximately 60–75% of total enterprise value. Check that cells where WACC ≤ g + 0.01 are flagged as invalid (Gordon Growth breaks down when g approaches WACC). Verify the grid shows larger value swings along g-axis than along WACC-axis.
- Human supplies: Nothing — fully synthetic. The FCFF projections and firm parameters are analytic. Optional: use Halverson's parameters from the book chapter for a more grounded illustration.
- Output medium: Manim (animated) — the sensitivity grid appears as a heat map (dark blue = low EV, bright amber = high EV); a cursor sweeps across the g-axis at fixed WACC and a cursor sweeps down the WACC-axis at fixed g; a side-by-side comparison shows the EV range from each sweep (g sweep range is ~3× wider than WACC sweep range); a text overlay reads "g drives more than WACC."
- The change: Re-run with the growth rate drawn from two scenarios (bull case: g=4% vs. bear case: g=1.5%) and show how one analyst's g assumption can justify valuations ranging from "undervalued" to "overvalued" for the same underlying firm. This is the inside/outside view problem applied to a single parameter.
- Teardown angle: Every DCF is dominated by a number (g) that is an assumption about the distant future, not a measurement. The sensitivity grid is not pessimism — it is honesty about which assumptions drive value. A CFO who presents one number without this grid is hiding the real source of uncertainty.
- Exclusions: Exit multiple methods (EV/EBITDA terminal value), SOTP valuation, full FCFF construction from scratch, real options approach to terminal value.
- Score: 9/10

## Candidate 02 — Build a WACC Sensitivity Calculator: Map the 7.5%–9.6% Range to Enterprise Value with Claude
- Source: corporate-finance-with-ai/chapters/05-the-cost-of-capital-and-the-wacc.md
- Lane: BUILD (Claude Code)
- Hook: The WACC formula looks precise — five inputs, one output. But each input is an estimate. The equity risk premium alone has a range from 4.5% to 6.0% depending on which academic's data you use. Combined across all inputs, a reasonable WACC for the same firm can span 7.5% to 9.6% — a range that moves enterprise value by 25%. Can we build a tool that shows this uncertainty rather than hiding it?
- The artifact: A Python script that computes WACC from its components (cost of debt, cost of equity via CAPM, capital structure weights) and generates a Monte Carlo simulation over input ranges: ERP range [4.5%, 6.0%], beta range [0.85, 1.15], risk-free rate range [3.5%, 4.5%], cost of debt range [4.5%, 5.5%], D/E range [0.3, 0.5]. Output is a WACC distribution (mean, std, 10th, 90th percentile) and its mapping to enterprise value for a fixed set of FCFFs. Manim animation shows the WACC distribution as an animated histogram, then converts each WACC draw to an EV and shows the resulting EV distribution.
- Prompt seed: `claude "Write a Python script that: (1) defines WACC = (E/(D+E)) × Re + (D/(D+E)) × Rd × (1 - tax_rate) where Re = Rf + beta × ERP (CAPM); (2) runs 10,000 Monte Carlo draws with: ERP ~ Uniform(0.045, 0.060), beta ~ Uniform(0.85, 1.15), Rf ~ Uniform(0.035, 0.045), Rd ~ Uniform(0.045, 0.055), D_weight ~ Uniform(0.30, 0.50), tax_rate=0.25; (3) for each WACC draw, computes enterprise value using FCFF = [120, 135, 148, 160, 170, TV] where TV = 170×1.025/(WACC-0.025); (4) prints WACC distribution (mean, std, p10, p90) and EV distribution (mean, std, p10, p90); (5) prints a frequency histogram of WACC draws as ASCII art. Use only random and math libraries."`
- Read / check: Verify the WACC formula includes the tax shield on debt (Rd × (1-tax_rate)). Confirm Re uses CAPM correctly: Rf + beta × ERP, not beta × (Rf + ERP). Check that the EV p10-to-p90 range spans at least 20% of the mean EV (the input uncertainty should create substantial output uncertainty). Verify the terminal value excludes cases where WACC < g.
- Human supplies: Nothing — fully synthetic. The input ranges are drawn from academic consensus (Damodaran ERP estimates, typical industrial beta range).
- Output medium: Manim (animated) — two histograms animate simultaneously: WACC distribution (left) and EV distribution (right); the 7.5%–9.6% WACC range is highlighted as a shaded region; vertical dashed lines mark the p10 and p90 of each; a connecting animation sweeps from a single WACC draw to the corresponding EV point on the right histogram.
- The change: Add a fourth output: the "precision illusion" test — compare the WACC computed from a single-point estimate vs. the Monte Carlo 90% confidence interval. Show that the single-point WACC implies precision (e.g., 8.3%) that the input uncertainty does not support (actual range: 7.5%–9.6%).
- Teardown angle: Precision is not accuracy. A WACC computed to two decimal places from estimated inputs is not more accurate than a range — it is less honest. The Monte Carlo output is not an admission of ignorance; it is the correct representation of what the inputs actually know.
- Exclusions: Hamada equation for leveraged beta, FAMA-French factor models, full Damodaran implied ERP methodology, CAPM critique.
- Score: 9/10

## Candidate 03 — Build a Cash Conversion Cycle Calculator: Find the Hidden Capital in Any Firm with Claude
- Source: corporate-finance-with-ai/chapters/03-working-capital-is-where-the-cash-lives.md
- Lane: BUILD (Claude Code)
- Hook: Halverson Manufacturing has $323 million locked inside its operating cycle at any given moment — more than its total long-term debt. This capital was not borrowed, not raised, not approved by the board. It is just sitting in transit between when cash goes out and when it comes back. A 10-day improvement in the cash conversion cycle releases $38 million. Can you find this number for any public company?
- The artifact: A Python script that fetches 3 years of financial data for a given ticker (DSO, DIO, DPO, COGS, Revenue, AR, Inventory, AP) using yfinance, computes the Cash Conversion Cycle (CCC = DSO + DIO - DPO), and computes the dollar value locked in the operating cycle (CCC × COGS / 365). Output is a 3-year trend table and a "working capital opportunity" estimate: if CCC improved by 10 days, how much cash would be unlocked? Manim animation shows three horizontal bars (DSO, DIO, DPO) animating to form the CCC timeline, with a dollar-value annotation below.
- Prompt seed: `claude "Write a Python script that: (1) uses yfinance to fetch 3 years of annual financials for a user-specified ticker (default: CAT for Caterpillar); (2) computes DSO = (Accounts Receivable / Revenue) × 365, DIO = (Inventory / COGS) × 365, DPO = (Accounts Payable / COGS) × 365, CCC = DSO + DIO - DPO for each year; (3) computes working capital locked = CCC × (COGS / 365) in $M; (4) computes the 10-day improvement opportunity: 10 × (COGS / 365) in $M; (5) prints a formatted 3-year table with all metrics. Flag any year where DPO > DIO + DSO (firm is being net funded by suppliers). Use yfinance and pandas."`
- Read / check: Verify DSO uses Accounts Receivable (not total receivables net of allowance) and Revenue in the denominator. Confirm DIO uses Inventory divided by COGS, not Revenue. Check that the 10-day improvement calculation multiplies by COGS/365, not Revenue/365. Verify the flag for negative CCC fires correctly (DPO > DIO + DSO means suppliers fund the firm — Amazon's historical pattern).
- Human supplies: An internet connection for yfinance. No API key required. The viewer can substitute any ticker — CAT, WMT, AMZN all produce interesting CCC patterns (Caterpillar ~85 days, Amazon historically negative). A 10-second yfinance download is the only runtime dependency.
- Output medium: Manim (animated) — a horizontal timeline per year: DSO extends right from zero (teal bar), DIO extends further right (amber bar), DPO extends left from DSO+DIO (reducing the total, green bar); the CCC is the net length; a dollar-value label animates in below the bar; three bars (one per year) stack vertically to show the 3-year trend.
- The change: Add a peer comparison: run the same CCC calculation for 3 firms in the same sector (e.g., CAT, DE, AGCO for industrials). Show how CCC varies within a peer group and estimate the cash released if the highest-CCC firm matched the lowest.
- Teardown angle: The largest pool of capital in most industrial firms is not the factory — it is the operating cycle gap. Working capital is the third source of financing (alongside debt and equity), requires no banker approval, and releases cash without diluting shareholders. The CCC calculator makes this visible in one number.
- Exclusions: Full accounts-receivable aging analysis, factoring and supply-chain finance, working capital securitization, days payable optimization strategy.
- Score: 9/10

## Candidate 04 — Build an M&A Synergy Haircut Calculator: Price the Gap Between Promise and Reality with Claude
- Source: corporate-finance-with-ai/chapters/11-m-and-a-the-largest-decisions-a-cfo-makes.md, chapters/14-behavioral-corporate-finance.md
- Lane: BUILD (Claude Code)
- Hook: Revenue synergies are promised at 100% and typically realized at 40–60%. Cost synergies arrive on schedule. This asymmetry is documented across hundreds of M&A deals. The acquirer's model assumes full realization. The correct model applies haircuts. Can we build a tool that shows the standalone value, the synergy value (haircut-adjusted), and the maximum price to pay — so the acquirer cannot overpay?
- The artifact: A Python script that takes standalone DCF value, projected synergies (split by type: cost vs. revenue), haircut rates (cost: 85%, revenue: 45%, per empirical literature), synergy probability of realization, and deal multiple, and computes: standalone value, haircut-adjusted synergy PV, maximum acquisition price, and premium implied by the asking price. Output is a deal valuation summary with a "are you overpaying?" verdict. Manim animation shows three stacked bars: standalone value (teal), haircut-adjusted synergies (amber, smaller than promised), and the gap between asking price and maximum price (red if deal destroys value).
- Prompt seed: `claude "Write a Python script that: (1) accepts: standalone_dcf=$850M, cost_synergies=$80M (Year 1–3, tax-effected PV at 8.5% WACC), revenue_synergies=$120M PV, deal_price=$1.1B; (2) applies haircuts: cost synergy haircut=15% (realization rate=85%), revenue synergy haircut=55% (realization rate=45%); (3) computes: haircut_adjusted_total_synergy_value = cost_synergies×0.85 + revenue_synergies×0.45; (4) computes max_acquisition_price = standalone_dcf + haircut_adjusted_total_synergy_value; (5) computes deal_premium = (deal_price - standalone_dcf) / standalone_dcf; (6) prints a deal summary: standalone value, raw synergies, haircut-adjusted synergies, max price, deal price, premium paid, verdict (value-creating if deal_price < max_price, else value-destroying). No external libraries."`
- Read / check: Verify cost synergy realization rate of 85% and revenue synergy rate of 45% are applied correctly. Confirm max_acquisition_price = standalone + haircut-adjusted synergies (not gross synergies). Check the verdict fires correctly: deal_price=$1.1B vs. max_price should determine the verdict. Verify the premium calculation is (deal_price - standalone) / standalone, not (deal_price - max_price) / max_price.
- Human supplies: Nothing — fully synthetic. The parameters are drawn from the book's Halverson/Cardinal deal framework. Optional: the viewer substitutes a real deal (e.g., a recent announced acquisition with public synergy estimates).
- Output medium: Manim (animated) — a stacked horizontal bar builds from left to right: standalone DCF value (teal), then raw synergies extend the bar (amber, full height), then the haircut shrinks the synergy bar (amber shrinks to 45% of revenue synergy and 85% of cost synergy width); a vertical red line marks the asking price; the gap between the adjusted max price and the asking price is shaded red if the deal overpays.
- The change: Run the tool across three haircut scenarios: optimistic (cost=95%, revenue=65%), base (cost=85%, revenue=45%), pessimistic (cost=70%, revenue=25%). Show the range of max prices and ask: at what haircut does the deal tip from value-creating to value-destroying?
- Teardown angle: The planning fallacy (Kahneman and Lovallo) predicts that deal teams will use inside-view synergy estimates that are 20–40% above the historical base rate. The haircut is not pessimism — it is reference-class forecasting applied to M&A. Most acquirers overpay. The ones who don't use a calculator like this one.
- Exclusions: Earnout structure, deal financing (debt vs. stock consideration), tax step-up, full integration risk framework, reverse synergies.
- Score: 9/10

## Candidate 05 — Build a Modigliani-Miller Tax Shield Calculator: Show When Debt Creates Value with Claude
- Source: corporate-finance-with-ai/chapters/07-capital-structure-theory-the-modigliani-miller-world.md, chapters/08-capital-structure-in-the-real-world.md
- Lane: BUILD (Claude Code)
- Hook: In a perfect world, debt is irrelevant — the cost of equity rises exactly to offset the benefit of cheap debt (MM Proposition II). Add one real-world friction — corporate taxes — and debt creates value equal to T_c × D. This is the fundamental argument for having any debt at all. Can we visualize the trade-off between the tax shield and distress costs that determines optimal capital structure?
- The artifact: A Python script that computes firm value as a function of debt level D under three scenarios: MM with no taxes (V_L = V_U), MM with taxes (V_L = V_U + T_c × D), and trade-off theory (V_L = V_U + T_c × D - PV(distress costs), where PV(distress costs) grows nonlinearly with D). Output is a table of D values, V_L under each model, and the optimal D that maximizes trade-off theory value. Manim animation shows three curves drawing simultaneously on a V(D) vs. D/E axis, with the optimal capital structure marked at the peak of the trade-off curve.
- Prompt seed: `claude "Write a Python script that: (1) defines V_U = 1000 (unlevered firm value, $M), T_c = 0.25, max_debt = 800; (2) for debt D in range(0, 801, 50): computes V_mm_no_tax = V_U (constant), V_mm_with_tax = V_U + T_c × D, V_tradeoff = V_U + T_c × D - distress_cost(D) where distress_cost(D) = 0.0003 × D^2 (a quadratic cost that grows steeply at high leverage); (3) finds the D that maximizes V_tradeoff; (4) prints a table: D, D/V ratio, V(no tax), V(tax shield), V(tradeoff); (5) prints the optimal leverage ratio. No external libraries."`
- Read / check: Verify V_mm_with_tax = V_U + T_c × D (linear in D, Proposition I with taxes). Confirm V_tradeoff has a maximum at an interior D (the quadratic distress cost should create a hump). Check that the optimal D is in the range 300–500 for these parameters (where the marginal tax shield equals the marginal distress cost). Verify the D/V ratio column is computed as D / V_tradeoff (not D / V_U).
- Human supplies: Nothing — fully synthetic. The functional form of distress costs (quadratic) is a standard simplification from the textbook trade-off theory presentation.
- Output medium: Manim (animated) — three curves animate drawing from left to right on a V vs. D axis: V_mm_no_tax is a flat horizontal line (teal); V_mm_with_tax rises linearly (dashed amber); V_tradeoff rises then falls (bold amber); a vertical dashed line marks the peak of the trade-off curve with a label "optimal D/V ≈ 38%"; a second panel shows the tax shield and distress cost curves separately — they cross at the optimal point.
- The change: Re-run with T_c = 0.15 (lower tax rate, e.g., post-TCJA for some firms) and T_c = 0.35 (pre-TCJA). Show how the optimal leverage ratio shifts with the corporate tax rate — higher taxes = more debt preferred = the tax shield is worth more.
- Teardown angle: The MM theorem is most useful not as a description of reality but as a map of it — it tells you exactly which frictions make debt valuable (taxes) and which make it costly (distress). The optimal capital structure is where the tax shield's marginal value equals the distress cost's marginal value. Everything else is a correction to this foundation.
- Exclusions: Pecking order theory, market-timing capital structure theory, agency costs of debt (Jensen-Meckling), convertible debt.
- Score: 8/10

## Candidate 06 — Build a Dividend Policy Signal Analyzer: Lintner's Smoothing Model in Action with Claude
- Source: corporate-finance-with-ai/chapters/09-returning-capital-dividends-buybacks-and-the-choice-between-them.md
- Lane: BUILD (Claude Code)
- Hook: John Lintner found in 1956 that managers smooth dividends — they adjust slowly toward a target payout ratio, never cutting unless forced. This means a dividend cut is not just a cash reduction; it is a confession that the promised future was wrong. Can we build a Lintner model that tracks any firm's dividend policy, detects cuts, and estimates the implied earnings forecast?
- The artifact: A Python script that fetches 5 years of dividend and EPS data via yfinance for a given ticker, fits a Lintner partial-adjustment model (ΔD_t = c + s × (target_payout × EPS_t - D_{t-1})), and computes: the target payout ratio, the smoothing coefficient s, and the implied EPS at which the current dividend is sustainable. Output is a 5-year dividend history table with predicted-vs-actual dividends, a sustainability verdict, and a cut-warning flag if current dividend exceeds 90% of the sustainable level. Manim animation shows actual dividends as a bar chart with Lintner model predicted dividends as an overlaid line, divergences highlighted.
- Prompt seed: `claude "Write a Python script that: (1) uses yfinance to fetch 5 years of quarterly dividends (ticker.dividends) and trailing EPS for a user-specified ticker (default: JNJ for Johnson & Johnson); (2) fits a simple Lintner model: for each year, target_dividend = target_payout_ratio × EPS, then delta_D = smoothing_coefficient × (target_dividend - prior_dividend); uses scipy.optimize.minimize to fit target_payout_ratio and smoothing_coefficient to minimize sum of squared errors between predicted and actual dividends; (3) computes the EPS at which the current dividend exactly equals the Lintner target (sustainability EPS); (4) prints a table: year, EPS, target dividend, actual dividend, predicted dividend, error; and a sustainability verdict. Use yfinance, numpy, scipy."`
- Read / check: Verify the Lintner model formula: ΔD_t = s × (p × EPS_t - D_{t-1}) where p is target payout ratio and s is smoothing coefficient (0 < s < 1 for partial adjustment). Confirm the optimizer bounds s ∈ [0, 1] and p ∈ [0, 1]. Check that the sustainability EPS calculation is: EPS_sustainable = D_current / target_payout_ratio. Verify JNJ shows s < 0.5 (high smoothing — slow adjustment) consistent with its reputation as a dividend aristocrat.
- Human supplies: An internet connection for yfinance. No API key required. JNJ, KO, or any dividend aristocrat works well as a demo ticker.
- Output medium: Manim (animated) — a bar chart of annual dividends per share (5 years) with the Lintner model target dividend overlaid as a dotted line and the predicted dividend as a solid line; divergences between actual and predicted are shaded red; below the chart, two parameter displays animate in: target payout ratio (%) and smoothing coefficient (s); a final annotation shows the sustainability EPS with a "current EPS vs. sustainability EPS" comparison.
- The change: Apply the model to a firm that cut its dividend (e.g., GE in 2018, Intel in 2023) and show how the Lintner model predicted the cut was coming — the dividend had been maintained above the Lintner target for 2+ consecutive years before the cut. The model is a leading indicator, not a lagging one.
- Teardown angle: Dividends are not residual cash distributions — they are commitments priced as an infinite series (Gordon Growth Model). Lintner's empirical finding that managers smooth dividends means the current dividend is a signal about management's confidence in future earnings. The cut-warning flag converts that signal into a checkable prediction.
- Exclusions: Dividend irrelevance (MM), clientele effects in depth, full event-study methodology for dividend announcements, share repurchase comparison.
- Score: 7/10

- Teardown angle: Reference class forecasting is not pessimism — it is the only calibrated way to counter the planning fallacy. The inside view feels more precise because it is specific. The reference class is more accurate because it includes outcomes the inside view is systematically blind to: the worst 30% of comparable projects that always look different in advance.

- Score: 7/10
