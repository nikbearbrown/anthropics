# What's Inside a Plugin Folder

**What this is.** A 158-second show-tell explainer that unpacks a Claude Code plugin, drawn as the same kraft box from the plugin-portal film, opened part by part. It has labels only, and Liam's voice does the explaining. **Why.** Card #4 in `../show-tell-ideas.md`, the direct sequel to `show-tell-claude-plugin-portal` (published youtu.be/TEHsl6rlfuI); Bear said to build all eight cards in order (2026-09-26). **Found.** Every claim matches `anthropics/claude-plugins-official` (README, the plugin-dev `plugin-structure` skill, real plugins) and `anthropics/knowledge-work-plugins/README.md`. A plugin is a folder: a `plugin.json` label in `.claude-plugin/` (only the name is required), slash commands you trigger, sub-agents Claude hands multi-step work to, skills Claude opens when the task matches, hooks that run a command on an event, and MCP servers that reach outside and start when the plugin is on. A plugin carries only the parts it needs (commit-commands: three commands; github: one MCP server). The official catalog lists 255 (attributed to its `marketplace.json`), and its README says to trust a plugin before installing it. Five overclaims were corrected (see FACTCHECK), including the knowledge-work README's "no code", which isn't true of hooks and MCP servers in general.
