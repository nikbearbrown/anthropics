# Zoom In

**What this is.** A show-tell explainer (about 3.5 minutes) of the zoom tool in Anthropic's cookbook `multimodal/crop_tool.ipynb`, following the LIVE upstream notebook. Claude sees an image once, in 28-by-28-pixel patches, and an image over the model's budget is scaled down, so a tiny label or two lines that nearly touch can be lost. The cookbook's fix is a tool. Your code keeps the full-resolution original and resizes a copy to exactly the size Claude sees (with `resized_size()` from the vision docs), so Claude's pixels line up with yours. Claude gets a tool named `zoom` whose inputs are pixel coordinates `x1, y1, x2, y2` from the top-left corner. When a detail is too small, Claude calls it on a box; your code maps the box onto the original, crops there, scales the crop up to the image budget, and returns it as a JPEG with one line of text. Claude may zoom again, tighter, then answers; in the cookbook's run it zoomed twice and answered Widget E, where without the tool it had said Widget A, which was wrong. A loop drives it (the runner stops after 20 rounds). The cookbook reports that the tool more than doubled accuracy on a public chart-reading benchmark, paid for in tokens and time. **Why.** Card #32 in `../show-tell-ideas.md` (Batch 2), built on Bear's overnight order of 2026-09-27. **Found.** The local repo copy is the OLD notebook (`crop_image`, normalized 0–1 inputs, no magnification); upstream rewrote it on 2026-07-23 around pixel coordinates and a magnified crop, and the live vision docs advise against normalized coordinates. The film follows the live notebook, says so in one line, and names no model.
