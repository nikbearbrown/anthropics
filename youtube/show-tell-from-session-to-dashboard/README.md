# From Session to Dashboard

**What this is.** A show-tell explainer (about 4.3 minutes) of how Claude Code's usage numbers reach a dashboard, following Anthropic's claude-code-monitoring-guide and checked against the live Claude Code monitoring docs. Telemetry export is opt-in: `CLAUDE_CODE_ENABLE_TELEMETRY=1` turns it on. The guide first tests with the console exporter (interval cut from the 60-second default to one second, one `claude -p` prompt), then `docker compose up` starts an OpenTelemetry collector, Prometheus and Grafana. Claude Code sends OTLP over gRPC to `localhost:4317`; the live docs list eight metrics, tagged by type, model and session ID. Events are a second stream through a separate logs exporter, which the guide's metrics-only collector doesn't carry. Privacy as the docs state it: prompt text isn't collected by default (only its length), raw file contents and code snippets aren't in metrics or events, and a signed-in email goes only to your endpoint. The collector batches (1 s timeout) and exposes port 8889; Prometheus scrapes it every 15 s; PromQL sums `claude_code_token_usage_tokens_total` by type; Grafana on port 3000 draws the guide's dashboard (cost is an approximation). Teams set the variables in managed settings; a repository can't turn telemetry on. Last, the guide's script feeds Prometheus totals and the Linear MCP to `claude -p` for a productivity report. **Why.** Card #28 in `../show-tell-ideas.md` (Batch 2), built on Bear's overnight order of 2026-09-27. **Found.** The local guide matches upstream byte for byte but is older than the live docs (seven metrics, an out-of-date managed-settings shape, an old clone URL); the film follows the docs.
