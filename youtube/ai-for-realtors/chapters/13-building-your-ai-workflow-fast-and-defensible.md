---

Two agents use AI on listing copy. Both use the same tool. Both produce a published ad. When a complaint arrives, they are not in the same position.

The first agent has a file: the source facts used as input, the AI-generated draft, notes from the Fair Housing audit, the original unedited photos, the final approved version, and a brief record of what was checked and changed. The second agent has the published ad and the memory of having looked it over.

The complaint might be the same. The positions are not. The first agent can show what they did, in what order, and what professional judgment they applied. The second agent is explaining after the fact, without documentation, to someone whose job is to evaluate whether professional standards were met.

This is what documentation is for. Not bureaucracy. Not compliance theater. A documented workflow is the evidence that the agent did their job — not just that the output was produced.

## Why Workflow Is the Right Unit of Analysis

The chapters before this one have focused on specific tasks: listing copy, CRM scoring, document summaries, virtual staging, market analysis. Each chapter named a specific risk and a specific audit. This chapter steps back and asks a structural question: how do you build a practice where those audits happen consistently, not just when you're thinking about it?

The answer is workflow — a defined sequence of steps that the agent follows every time a specific type of AI output is involved. Not a policy document that lives in a drawer. A habit so practiced that it becomes the default, not the exception.

NIST's AI Risk Management Framework provides a governance vocabulary useful here: govern, map, measure, manage. That framework was built for enterprise AI deployment, not solo real estate practice. But the underlying logic scales down cleanly. Govern means deciding what AI is used for and what it is not. Map means understanding where in the workflow AI output creates risk. Measure means building in the check that catches the risk. Manage means keeping evidence that the check happened. A solo agent does not need enterprise paperwork. They need those four functions operating as habit.

## The Two Lists

Every AI workflow starts with a classification decision. Before the agent produces anything with AI assistance, they need to know which category the task falls in. The classification determines what the workflow looks like — not whether to use AI, but how carefully to use it and what needs to be in the file.

The framework from Chapter 1 applies here in its simplest form: Delegate and Guard.

**The Delegate list** contains tasks where AI can produce a useful first pass and the audit is straightforward. First drafts of listing copy, email templates, social captions, market update summaries, contact follow-up sequences, meeting prep notes, scheduling, and source-bound document summaries — these are tasks where the tool is reliable enough to start, the risk is manageable with review, and the workflow is: input verified source material, review output against checklist, edit, document, publish.

**The Guard list** contains tasks where AI output cannot become the deliverable, regardless of how good it looks. Legal advice, pricing opinions, Fair Housing determinations, unverified zoning or HOA representations, negotiation judgment, client-specific financial recommendations, and any decision that requires professional accountability — these are Guard tasks. The tool can assist with research, with drafting, with organizing information. The output cannot go to a client without the agent's explicit professional judgment replacing or substantially transforming what the tool produced.

The classification is not static. A task that is Delegate under one set of conditions can become Guard when the context changes. A market summary for internal reference is Delegate. A market summary that a client will rely on in a purchase decision is Delegate with Review at minimum, and Guard if the agent is making a specific directional recommendation about value. The workflow has to build in the question: what is this output going to be used for, and does that change the classification?

## The File Habit

Classification tells you what category the task is in. The file habit is what you do about it.

A defensible file for an AI-assisted workflow contains six elements. Not all of them apply to every task — a CRM follow-up email does not require the same documentation as a listing that generates a complaint — but the agent should know what the full set is and apply it proportionately.

**Source material.** The verified facts, documents, or data that were used as input to the AI. For listing copy: the property record, MLS data, agent's own property notes. For a market summary: the verified vacancy and transaction data. For a document summary: the actual document that was summarized. The source material is what the agent can point to when a claim in the output is questioned.

**AI output when practical.** For higher-stakes outputs — listing copy, client-facing summaries, anything that generates a professional representation — keeping a copy of what the tool produced before the agent's edits makes the audit trail complete. This is not necessary for every email or scheduling note. It is necessary for any output that becomes a representation.

**Audit checklist.** The record that the specific checks required for this type of output were performed. For listing copy: Fair Housing review, factual accuracy, pricing framing, AB 723 compliance. The checklist can be a simple text note in the transaction file. The point is that it documents the specific things the agent verified, not just that the agent "reviewed" the output.

**Original media.** For listing photos and video: the original unedited files, preserved alongside the edited versions. This is the archive requirement from Chapter 7, incorporated into the workflow.

**Final approved version.** The output as it was published or delivered to the client, after all edits. This is what the agent actually produced, as distinct from what the tool produced.

**Notes on human judgment.** For any task where the agent made a specific professional judgment — this phrase was changed because of a Fair Housing concern, this price claim was removed because it wasn't defensible from comps, this market summary was modified to reflect local knowledge that differed from the model — a brief note recording what was changed and why. Not a legal memo. A contemporaneous record that the agent thought about what they were doing.

## The Listing Copy Workflow in Full

It helps to see a complete workflow, not just its components. Listing copy is the right example because it combines the most common AI use case with the most specific compliance obligations.

Here is the sequence.

**Step 1: Assemble source material.** Pull the property record for square footage, bedroom and bathroom count, lot size, and year built. Add agent inspection notes for any condition observations that will appear in copy. Note the pricing strategy — where the list price sits relative to comps and what the agent wants to communicate about value positioning.

**Step 2: Generate draft.** Input the verified source material into the AI tool with a prompt specifying the output type (MLS description, social caption, email to sphere), the tone, and any specific elements to include or avoid. Keep the prompt.

**Step 3: Fair Housing audit.** Read the output specifically for the phrase types from Chapter 1's Fair Housing table: neighborhood demographic characterization, family status language, suitability-for-specific-populations framing, school or demographic references, proximity framing that implies segregation. Change or remove any phrase that triggers a concern. Document what was changed.

**Step 4: Factual accuracy check.** Verify every specific claim against the source material. Square footage: matches property record. "Updated kitchen": the update is documented and visible. "Walking distance to shops": accurate for the specific property's location. Mark anything you verified.

**Step 5: Pricing framing check.** Review any language that implies value or market position. If the copy says "priced to sell" or "below market" or "best value in the neighborhood," the agent needs to be able to defend that claim from comps. If they can't, the language comes out.

**Step 6: AB 723 compliance check.** If any images used in the listing have been digitally altered beyond standard photographic correction, the disclosure requirement applies. Confirm that disclosure language is in place before publication.

**Step 7: Final edit and approval.** Make all changes. Produce the final version the agent is willing to stand behind.

**Step 8: File.** Source facts, original AI draft, checklist with what was checked and changed, final published version. Transaction file.

That sequence takes more time than publishing the first draft. It takes less time than responding to a complaint without documentation. And it takes progressively less time as it becomes habit — because the agent isn't thinking through the steps each time, they're executing a sequence they know.

## Workflow for Teams and Small Offices

The solo agent workflow described above is the baseline. For a team or small office, the workflow needs one additional element: supervision.

The California Department of Real Estate's supervision requirements apply to AI-assisted work the same way they apply to any work produced by licensed and unlicensed assistants. A broker who allows team members to use AI tools without defined Delegate and Guard lists, without audit protocols, and without file requirements has created a supervision gap that the broker's license is responsible for.

The team workflow adds three things to the solo baseline.

**Defined Delegate and Guard lists for the team.** The classification cannot be left to each agent's individual judgment. The team needs a shared document that specifies what is Delegate, what is Guard, and what requires broker review before publication. This does not need to be elaborate. It needs to exist and be followed.

**Broker review triggers.** Certain task types — anything involving Fair Housing determinations, any output that will be used in a disclosure, any market analysis that a client will rely on for a purchase or sale decision — should have an explicit trigger requiring broker review before the output is published or delivered. The trigger is built into the workflow, not left to the agent's discretion.

**Audit cadence.** Small teams benefit from periodic review of AI-assisted outputs — not surveillance of individual agents, but a regular check that the workflow is being followed and that the files contain the expected documentation. Quarterly is reasonable for an active team. The audit is not punitive. It is the team equivalent of the solo agent's own quality-check habit.

## Keeping the Workflow Current

A workflow built for today's tools and today's legal landscape needs updating as both change. This is not a hypothetical — California AB 723 is a 2025 statute. HUD's digital advertising guidance was issued in 2024. The NAR settlement implementation is ongoing. New tools are being adopted by the major CRM and listing platforms continuously.

The practical approach: annual review of the Delegate and Guard lists against any new regulatory guidance, any new tools the agent has adopted, and any compliance events — complaints, close calls, or industry-level enforcement actions — that suggest the risk landscape has shifted. The review does not need to be comprehensive. It needs to cover the specific places where the workflow touches legal or ethical obligations.

For California agents specifically: the California Department of Real Estate's current guidance on AI tools and the specific requirements of AB 723 should be verified against current materials before publication, because both may have implementing guidance or enforcement decisions that postdate this chapter's writing. The workflow is only as current as the rules it's built on.

## Repeatability Is the Point

There is a temptation to treat the workflow as a compliance exercise — something you build once to satisfy a regulatory obligation and then check off. That framing misses what the workflow is actually for.

The workflow is how a consistent professional practice becomes consistent. The agent who improvises their Fair Housing audit — sometimes careful, sometimes not, depending on how rushed they are — is not practicing professionally. They are gambling on the distribution of their own attention. The agent who runs the same checklist every time is not slower or more cautious. They are reliable in a way that the improvising agent is not.

Feynman had a version of this principle in the context of scientific practice: the goal is not to avoid mistakes through exceptional effort. The goal is to build procedures that catch mistakes automatically, so that exceptional effort is not required. The workflow is that procedure. It does not require the agent to be maximally careful on every task. It requires the agent to follow the sequence, which catches the problems that carelessness would miss.

The agent with a documented workflow is faster than the agent without one — because they are not reconstructing the right approach from scratch every time. They are executing a sequence they have practiced. And they are protected in ways the undocumented agent is not — because when the complaint arrives, the file answers the question before the agent has to.

## What Would Change This Chapter

The workflow described here would simplify substantially if residential platforms automatically generated complete, reliable compliance records for AI-assisted work. If the MLS platform that hosts listing copy maintained a timestamped audit log of what the AI produced, what the agent changed, and what compliance checks were performed — built into the platform rather than maintained separately by the agent — the file habit would be handled by the tool rather than by the agent.

That capability does not currently exist at the level of completeness and reliability required to substitute for agent documentation. Until it does, the file habit is the agent's responsibility.

## LLM Exercises

**Apply:** Build your own Delegate and Guard lists for your current practice. Start with the ten to fifteen most common tasks in a typical transaction. Classify each one, write the specific audit steps for each Delegate task, and identify the two or three Guard tasks that you have historically treated as Delegate. For each Guard task you identified, write a one-sentence rule you would follow instead.

**Analyze:** Take the listing copy workflow from this chapter and apply it to the last listing you produced. Work backward: does the transaction file contain all eight elements the workflow generates? Identify specifically which elements are missing and what it would have taken to produce them. What does the gap tell you about where your current workflow breaks down?

**Create:** Draft a one-page AI workflow policy for your practice or team. It should contain: your Delegate list, your Guard list, the audit checklist for at least two common Delegate tasks, the file requirements for any AI-assisted output that becomes a client representation, and a date for annual review. Write it as a document you would hand to a new team member on their first day.
