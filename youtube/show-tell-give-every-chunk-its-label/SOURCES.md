1. **`anthropics/claude-cookbooks/capabilities/contextual-embeddings/guide.ipynb`** — "Enhancing RAG with Contextual Retrieval" (Anthropic's Claude cookbook). Read in full on 2026-09-27: all 33 cells (markdown, code and printed outputs) dumped from the raw JSON. Used:
   - intro cell: chunking in traditional RAG; "it can lead to problems when individual chunks lack sufficient context"; "Averaged across all data sources we tested, Contextual Embeddings reduced the top-20-chunk retrieval failure rate by 35%." (the only number shown on screen);
   - "Contextual Embeddings" cell: Claude generates "a brief description that 'situates' each chunk within its source document"; "we pass both the chunk and its full source file to Claude"; "This context gets prepended to the chunk before embedding"; the cost is "a one-time cost when building your vector database"; "Prompt caching makes this practical": first chunk writes the full document to cache ("pay a small premium"), later chunks "Read the document from cache (90% discount on those tokens)";
   - `CHUNK_CONTEXT_PROMPT`: "Please give a short succinct context to situate this chunk within the overall document for the purposes of improving search retrieval of the chunk. Answer only with the succinct context and nothing else.";
   - `process_chunk`: `"text_to_embed": f"{contextualized_text}\n\n{chunk['content']}"` (the note goes in front of the chunk);
   - "Contextual BM25" cells: BM25 "Catches exact terminology, function names, and specific phrases"; semantic search "can miss exact keyword matches"; "we search both the chunk *and* the contextual description"; Reciprocal Rank Fusion merges the two rankings;
   - "Reranking" cells: over-retrieve, a reranking model scores the candidates and keeps the top k; it "has access to both the original chunk content and the contextual descriptions"; rerankers are "slower but more accurate".
   **Not used, on purpose:** every other figure in the notebook (the Pass@k tables, 87%→95%, "~30-40%", "47% reduction", 61.83% cache reads, the $ estimates, 737 chunks, 248 queries, the 5-minute cache life, 100–200 ms). Several disagree with each other inside the notebook (the intro says contextual embeddings took Pass@10 "from ~87% --> ~95%", but its own table gives 92.34% for embeddings and 95.26% only with reranking; the reranking cell quotes "93.21% Pass@10" for hybrid search where the printed run shows 92.31%), so the film uses only the 35% headline the brief names, with its exact framing. The model name, Voyage and Cohere product names are left out.
   **A note on the notebook's pipeline:** in the notebook, reranking is demonstrated on the contextual-embedding results alone, "not the full hybrid search". The film presents BM25 and reranking as two further steps without saying the reranker reads the merged list.
