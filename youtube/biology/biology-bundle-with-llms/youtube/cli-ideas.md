## Candidate 01 — "Build a Hardy-Weinberg Equilibrium Tester with Claude"
- Source: biology-bundle-with-llms/chapters/23-the-evolution-of-populations.md + LLM Exercise
- Lane: BUILD (Claude Code)
- Hook: Hardy-Weinberg equilibrium is the null hypothesis of population genetics — the baseline for no evolution. But most students never actually test whether a real dataset departs from it. Claude can build the chi-square tester in under 30 lines.
- The artifact: A Python script (`hw_test.py`) that takes observed genotype counts (AA, Aa, aa) as inputs, computes expected HW frequencies, runs a chi-square goodness-of-fit test, reports p-value and whether to reject HWE, and flags which HWE assumption is most likely violated based on the direction of departure.
- Prompt seed: `claude "Build hw_test.py: a Python script that tests whether a population is in Hardy-Weinberg equilibrium. Input: counts of three genotypes (AA, Aa, aa). Output: allele frequencies p and q; expected genotype frequencies p^2, 2pq, q^2; expected counts; chi-square statistic; degrees of freedom (=1); p-value; decision to reject or fail-to-reject HWE at alpha=0.05. If HWE is rejected, print which departure pattern is detected (excess heterozygotes → inbreeding coefficient estimate; deficit heterozygotes → outbreeding or selection against heterozygotes). Include a worked example with ABO blood type data from a real population."`
- Read / check: Verify the chi-square formula is correct (sum of (observed-expected)^2/expected over 3 genotype classes, df=1 after estimating p from data). The ABO worked example should use a real published dataset. The inbreeding coefficient F = (He - Ho)/He should be computed and commented.
- Human supplies (Claude can't): The worked example requires a real genotype count dataset — Claude should either use a published ABO or HLA dataset or flag that the user should supply one. Synthetic data is acceptable for the video demonstration if real data is noted as preferred.
- Output medium: screen-recording mp4 (terminal running the script with the ABO example, then a bar chart animating observed vs. expected genotype frequencies with the chi-square result annotating the gap)
- The change: Ask Claude to extend the script to simulate genetic drift over N generations using Wright-Fisher sampling and plot how allele frequency drifts away from HWE expectations.
- Teardown angle: HWE is routinely used as a quality-control step in GWAS studies — if a SNP deviates from HWE in controls, it usually means a genotyping error, not real biology. The equation that models "no evolution" is now a standard lab QC tool.
- Exclusions: Linkage disequilibrium, multi-locus HWE, selection coefficient estimation.
- Score: 9/10

## Candidate 02 — "Build a Population Growth Model: Logistic vs. Exponential with Claude"
- Source: biology-bundle-with-llms/chapters/53-population-and-community-ecology.md + LLM Exercise
- Lane: BUILD (Claude Code)
- Hook: Asian carp now constitute 95% of fish biomass in parts of the Illinois River. Exponential growth explains how. Logistic growth explains what stops it — and when. Claude can simulate both in a single script and show the cliff where density dependence kicks in.
- The artifact: A Python script (`pop_growth.py`) that simulates exponential growth (dN/dt = rN) and logistic growth (dN/dt = rN(1-N/K)) side by side, plots N vs. time for configurable r, K, and N0, marks the inflection point (K/2) on the logistic curve, and includes a silver carp invasion preset (r ≈ 0.7/year, K = carrying capacity of Illinois River reach in biomass kg/km).
- Prompt seed: `claude "Build pop_growth.py: a Python script that simulates and plots exponential and logistic population growth. Inputs: r (intrinsic growth rate), K (carrying capacity), N0 (initial population), t_max (years). Plot both curves side by side; mark the logistic inflection point at K/2 with a dashed line. Include a silver carp preset using published r estimates (~0.7/year) and flag K as VERIFY. Add a third panel showing dN/dt vs N for the logistic curve to show how growth rate peaks at K/2 then falls."`
- Read / check: Verify the logistic equation implementation (dN/dt = rN(1-N/K), solved numerically). The inflection point mark should be at exactly K/2. The silver carp r value should be cited or flagged VERIFY. The dN/dt panel should show a parabola peaking at K/2.
- Human supplies (Claude can't): The carrying capacity K for the Illinois River silver carp population requires literature values from fisheries management reports — Claude should flag this and use a plausible estimate. Real population survey data from USGS would strengthen the video but synthetic demonstration is acceptable.
- Output medium: screen-recording mp4 (terminal running the script, then animated matplotlib showing both growth curves with the silver carp invasion context, inflection point animating in)
- The change: Ask Claude to add a stochastic version using Poisson sampling at each timestep, run 100 simulations, and plot the ensemble with confidence intervals to show how small populations can stochastically go extinct even below K.
- Teardown angle: The logistic model is the simplest possible addition of density dependence — one parameter, K — and it immediately shows why no population grows forever. The silver carp isn't an exception to ecology; it's ecology operating on an introduced species before the brakes have been installed.
- Exclusions: Age-structured models, Lotka-Volterra competition, metapopulation dynamics.
- Score: 9/10

## Candidate 03 — "Build a DNA Replication Error Rate Calculator with Claude"
- Source: biology-bundle-with-llms/chapters/17-dna-structure-and-function.md + LLM Exercise
- Lane: BUILD (Claude Code)
- Hook: DNA polymerase makes 1 error per 10^5 bases before proofreading, 1 per 10^7 after, and mismatch repair brings it to 1 per 10^9. Over a human lifetime of ~10^16 cell divisions, how many mutations does that actually produce? Claude can compute it exactly.
- The artifact: A Python script (`mutation_calc.py`) that computes the expected number of mutations per division, per tissue, per lifetime, given genome size, per-base error rate, proofreading efficiency, and mismatch repair efficiency. Includes presets for human somatic cells, human germline cells, and E. coli. Reports: mutations per division, mutations per tissue per year (given division rate), and lifetime somatic mutation burden.
- Prompt seed: `claude "Build mutation_calc.py: a Python script that calculates mutation rates across the human genome. Inputs: genome_size_bp (default 3e9), polymerase_error_rate (default 1e-5), proofreading_reduction (default 100x), mmr_reduction (default 1000x). Compute: final error rate per bp; expected mutations per cell division; for each tissue preset (colon epithelium: ~1 division/day/cell; skin keratinocytes: ~60 divisions/year; neurons: ~0 post-development), compute annual and lifetime mutation burden. Include E. coli comparison (genome 4.6e6 bp, r=1 division/20 min). Output as a formatted table."`
- Read / check: Verify the final per-bp error rate is ~10^-9 (from 10^-5 × 1/100 × 1/1000 = 10^-10; note polymerase makes ~3 errors per division in a 3Gb genome). The colon epithelium estimate should be consistent with published somatic mutation accumulation data (~40 mutations/year in colon — cite Tomasetti & Vogelstein 2015 or equivalent). Flag any values that need literature verification.
- Human supplies (Claude can't): Division rates per tissue require published estimates — Claude should use Tomasetti & Vogelstein 2015 values or flag VERIFY. The relationship between division rate and cancer risk is contested and the script should note this.
- Output medium: screen-recording mp4 (terminal running the script, then an animated bar chart showing mutation burden per lifetime by tissue type, with cancer incidence rates overlaid as a second dataset)
- The change: Ask Claude to add a mutagen comparison: how does the error rate change if UV exposure increases pyrimidine dimer frequency by 100x in skin cells? What is the new annual mutation burden for a sun-exposed keratinocyte?
- Teardown angle: The mutation calculator shows that cancer is not a malfunction — it is the statistical inevitability of copying 3 billion letters ~10^16 times. The real puzzle is not why people get cancer; it is why so many don't.
- Exclusions: Mutational signatures, selection coefficients for driver mutations, tumor suppressor dosing.
- Score: 8/10

- Prompt seed: `claude "Research the actual ATP yield from complete glucose oxidation. Produce: (1) theoretical maximum calculation — substrate-level phosphorylation (4 ATP), NADH yield × P/O ratio, FADH2 yield × P/O ratio, with the classical P/O values (2.5 for NADH, 1.5 for FADH2) that replace the old 3 and 2; (2) sources of efficiency loss: proton leak, ADP/ATP translocator cost, pyruvate transport; (3) best empirical P/O ratio measurements with citations (Brand 2005, or equivalent); (4) comparison table of theoretical vs. measured ATP yield in hepatocytes, skeletal muscle, and neurons. Flag any contested values."`
- Read / check: The theoretical calculation with revised P/O ratios should give ~30–32 ATP, not 36–38. The sources of efficiency loss must include the ADP/ATP antiporter cost (cited as 1 proton per ATP exported). The Brand 2005 citation or equivalent (e.g., Rich 2003) should be verifiable.
- Human supplies (Claude can't): Nothing — fully synthetic. All cited P/O ratio measurements exist in the biochemistry literature.
- Output medium: Manim (animated cellular metabolism diagram showing glucose entering glycolysis, electrons flowing through ETC, with an ATP counter animating upward but stopping short of the theoretical maximum and labeling the losses)
- The change: Ask Claude to find one organism where the P/O ratio is significantly different from 2.5/1.5 — either higher (e.g., some thermophiles) or lower (e.g., brown adipose tissue deliberately uncoupled by UCP1) — and explain why.
- Teardown angle: The textbook number (36–38 ATP) was calculated in the 1950s from stoichiometry, before anyone could measure mitochondrial proton flux directly. - Exclusions: Fermentation yield comparisons, photosynthetic ATP synthesis, ATP demand accounting.
- Score: 8/10

## Candidate 05 — "Build a Mark-Recapture Population Estimator with Claude"
- Source: biology-bundle-with-llms/chapters/53-population-and-community-ecology.md + LLM Exercise
- Lane: BUILD (Claude Code)
- Hook: The Lincoln-Petersen mark-recapture estimator is used to count everything from fish in rivers to endangered condors to people in censuses. Claude can build the estimator, run it on real data, and show exactly where the assumptions break.
- The artifact: A Python script (`mark_recapture.py`) that implements the Lincoln-Petersen estimator N = (M×C)/R with confidence intervals (Chapman correction for small samples), tests the assumption of equal capture probability using a goodness-of-fit test, and includes a simulation mode that shows how violating each assumption (non-random capture, marked animals more/less catchable) biases the estimate.
- Prompt seed: `claude "Build mark_recapture.py: a Python script implementing the Lincoln-Petersen mark-recapture population estimator. Inputs: M (first-catch marked), C (second-catch total), R (second-catch recaptured). Outputs: Chapman-corrected estimate N, 95% confidence interval, coefficient of variation. Add a simulation mode: given true_N=1000, M=80, p_capture=0.1, run 1000 simulations of second-catch sampling, plot the distribution of estimates, and show bias if p_capture_marked differs from p_capture_unmarked. Include a worked example with real data from a published study."`
- Read / check: Verify the Chapman correction formula: N_hat = (M+1)(C+1)/(R+1) - 1. The confidence interval should use the method in Krebs (1999) or equivalent. The simulation should demonstrate that if marked animals are easier to recapture (trap-happy), the estimate is biased downward. The worked example should cite a real published dataset.
- Human supplies (Claude can't): The real worked example dataset requires published mark-recapture data — Claude should either use a well-known published dataset (e.g., Seber's classic fish data) or flag the need for user-supplied data. The simulation mode is fully synthetic.
- Output medium: screen-recording mp4 (terminal running the script, then matplotlib showing the simulation distribution of estimates with the true N marked and the bias visible when capture probability assumptions are violated)
- The change: Ask Claude to extend to the Schnabel multi-sample method for open populations (with births, deaths, and immigration between capture events) and show how the estimate changes.
- Teardown angle: Mark-recapture is used to estimate human trafficking victims, COVID infection prevalence, and the size of underground drug markets — the same equation that counts fish in rivers. The assumption of equal catchability is almost always violated, and the bias is usually predictable.
- Exclusions: Jolly-Seber open population models, telemetry-based continuous tracking, distance sampling.
- Score: 8/10

## Candidate 07 — "Build a Gibbs Free Energy Calculator for Cell Reactions with Claude"
- Source: biology-bundle-with-llms/chapters/08-metabolism.md + LLM Exercise
- Lane: BUILD (Claude Code)
- Hook: The second law of thermodynamics says disorder always increases — so how does a cell stay ordered? The answer is ΔG, and Claude can build a calculator that makes it concrete: type in any biochemical reaction and find out whether it runs spontaneously.
- The artifact: A Python script (`gibbs_calc.py`) that takes ΔH and ΔS as inputs at a given temperature, computes ΔG = ΔH - TΔS, classifies the reaction (always spontaneous, never spontaneous, temperature-dependent), and includes a cellular reactions table with real ΔG° values (ATP hydrolysis, glucose oxidation, protein synthesis).
- Prompt seed: `claude "Build gibbs_calc.py: a Python script that computes Gibbs free energy change. Inputs: delta_H (kJ/mol), delta_S (J/mol/K), T (Kelvin, default 310). Output: delta_G (kJ/mol); spontaneity classification (always/never/temperature-dependent with crossover T). Include a table of real biochemical reactions with their standard delta_G values: ATP hydrolysis (-30.5 kJ/mol), glucose combustion (-2870 kJ/mol), peptide bond formation (+10 kJ/mol), ADP phosphorylation (+30.5 kJ/mol). Show how ATP hydrolysis coupling makes peptide bond formation thermodynamically favorable."`
- Read / check: Verify the ATP hydrolysis ΔG° value (-30.5 kJ/mol under standard conditions). The coupling calculation should show that ATP hydrolysis + peptide bond formation gives a net ΔG < 0. The spontaneity classification should correctly identify the crossover temperature T = ΔH/ΔS for cases where both have the same sign.
- Human supplies (Claude can't): Nothing — fully synthetic. Standard ΔG° values for biochemical reactions are in published thermodynamics tables.
- Output medium: screen-recording mp4 (terminal running the calculator with each reaction in the table, then a four-quadrant ΔH vs. ΔS diagram animating with each reaction placed in its quadrant)
- The change: Ask Claude to add a cellular context mode: given the actual intracellular concentrations of ADP, ATP, and Pi in a resting cell, compute the actual ΔG (not the standard ΔG°) for ATP hydrolysis under physiological conditions.
- Teardown angle: The cell doesn't violate the second law — it exports entropy. Every ordered structure in a cell is paid for by making the surroundings more disordered. The Gibbs equation makes this accounting visible and quantitative.
- Exclusions: Electrochemical potentials, redox chemistry, non-equilibrium thermodynamics.
- Score: 8/10
