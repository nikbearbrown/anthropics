# Legacy Code, in Order

**What this is.** A show-tell explainer (about 3.3 minutes) of the order Anthropic's code-modernization plugin enforces on a legacy codebase, and the six points where a person decides. A dark mainframe cabinet sits locked in a `legacy/` tray; each step drops its page into an `analysis/` tray; the new code lands in a `modernized/` tray. Then one step per beat: **preflight** asks five questions only a person can answer and proves a build works (decision one); **assess** sends three agents to read at once and recommends a pattern, and **map** turns calls, data and entry points into an interactive map with business flows; **extract-rules** lifts the business rules onto Given/When/Then cards with file-and-line citations, each re-checked, and **review** has a person mark the doubtful ones (decision two); the **brief** writes a phased plan with a behaviour contract of P0 rules and stops until you approve (decision three); the build goes through one of three doors, **uplift**, **transform** or **reimagine**, each bound by the brief; **verify**, the proof, reruns the tests from clean, compares old and new byte for byte, invents at least ten new inputs, breaks one line on purpose, and gives each module one verdict that a person accepts and signs (decisions four and five); last, **harden** scans the legacy system and hands you a reviewed patch to apply yourself (decision six). Labels only; Liam's voice does the explaining. **Why.** Card #24 in `../show-tell-ideas.md` (Batch 2), built on Bear's overnight order of 2026-09-27. **Found.** The card and the local copy of the plugin describe an older version (harden last, no `review`, no `verify`, bare `/modernize-*` names). The live plugin (v1.0.0, GitHub main, 2026-09-25) makes the proof its own step, `verify`, before `harden`, and namespaces the commands `/code-modernization:modernize-*`. The film follows the live files, per the batch rule that live docs win; the difference is logged in `SOURCES.md`.
