## Candidate 01 — "Build Simpson's Paradox Detector with Claude Code"
- Source: Causal-Inference/chapters/03-confounding-and-adjustment.md
- Lane: BUILD (Claude Code)
- Hook: The drug is bad for men. The drug is bad for women. But across everyone, the drug looks good. Same numbers, two opposite conclusions — and the resolution requires knowing something the data doesn't contain.
- The artifact: a Python script (~35 lines) that takes a 2×2×2 contingency table (treatment × outcome × stratum) as input and: (1) computes the marginal (pooled) treatment effect and the stratum-specific effects, (2) detects whether Simpson's paradox is present (pooled and stratum effects have opposite signs), (3) calls Claude to ask whether the stratifying variable is more likely a confounder or a mediator given a user-supplied description, and (4) computes the adjusted ATE using stratification when the confounder diagnosis is confirmed — output as a Manim animated table where the pooled rows appear first, then stratum rows reveal the reversal.
- Prompt seed: `claude "Write a Python script that: (1) takes a 2x2x2 contingency table (treatment/outcome/stratum) as a dict; (2) computes marginal and stratum-specific treatment effects; (3) flags Simpson's paradox if the pooled and stratum effects have opposite signs; (4) calls Claude via the anthropic SDK asking whether the stratum variable is a confounder or mediator given a description string; (5) if confounder, computes the adjusted ATE using the backdoor stratification formula. Also generate a Manim scene that shows the pooled table first, then reveals the stratified breakdown with the reversal annotated."`
- Read / check: CODE: verify the stratification formula — ATE = Σ_z E[Y|X=1,Z=z]·P(Z=z) - Σ_z E[Y|X=0,Z=z]·P(Z=z) — matches the chapter's worked example (-0.15 for the drug case); verify Claude correctly classifies a "blood pressure measured after treatment" description as mediator and refuses to compute the adjusted ATE. OUTPUT: confirm the Manim scene shows the pooled table first, then the stratified rows appearing with the reversal highlighted in a contrasting color.
- Human supplies: Nothing — fully synthetic. The chapter's drug example provides exact numbers; the script works on any 2×2×2 table.
- Output medium: Manim (animated two-panel: top panel = pooled table with green "drug looks good" annotation; bottom panel = stratified rows appearing one by one, each row showing the opposite direction, with a vermillion "reversal" annotation)
- The change: Add a sensitivity analysis: "How far would the marginal distribution P(Z) have to shift before the Simpson's reversal disappears? Compute the critical P(Z=0) threshold."
- Teardown angle: The data doesn't tell you which diagram is right. The same table is consistent with two opposite causal structures, and the gap between them is a difference in how the world works — not a difference in the numbers. The script forces you to supply the diagram; the numbers alone are silent on which answer is correct.
- Exclusions: Continuous confounders; propensity score estimation; regression adjustment vs. stratification comparison.
- Score: 10/10

## Candidate 02 — "Build a DAG Path Analyzer with Claude Code"
- Source: Causal-Inference/chapters/02-the-language-of-causal-diagrams.md
- Lane: BUILD (Claude Code)
- Hook: Conditioning is not a clean operation. It removes some associations and creates others. Which it does depends on the structure — and you can't know which without drawing the diagram.
- The artifact: a Python script (~40 lines) using NetworkX to represent a user-supplied DAG (as edge list), then: (1) enumerates all paths between a specified treatment and outcome node, (2) classifies each path as directed (causal), back-door, or through-collider, (3) applies the d-separation rules to determine which paths are open given a conditioning set Z, and (4) calls Claude to generate a plain-English interpretation of the identification result — output as a Manim animated graph with paths highlighted in sequence.
- Prompt seed: `claude "Build a Python script using NetworkX that: (1) takes a DAG as a list of (from, to) tuples and a treatment node, outcome node, and conditioning set Z; (2) enumerates all paths from treatment to outcome; (3) classifies each path as directed-causal, back-door, or through-collider; (4) applies d-separation rules to determine if each path is open or blocked given Z; (5) calls Claude via the anthropic SDK to generate a two-sentence plain-English interpretation of whether the causal effect is identified. Also generate a Manim scene animating each path type with color-coding."`
- Read / check: CODE: verify d-separation logic — chain/fork blocked by conditioning, collider blocked by NOT conditioning, collider descendant conditioning opens collider path. Test on the chapter's smoking/tar/cancer/genotype diagram: conditioning set {G, T} should d-separate S from C. Verify Berkson's paradox: Disease_A and Disease_C d-separated when not conditioning on Hospital, associated when conditioning on Hospital. OUTPUT: confirm the Manim animation color-codes directed paths green, back-door paths orange, collider-created paths red.
- Human supplies: Nothing — fully synthetic. The script works on any DAG the user specifies as an edge list. The chapter provides three worked examples (smoking, job training, Berkson's) as test cases.
- Output medium: Manim (animated DAG: nodes appear, edges draw in, then paths light up sequentially — green for directed causal, orange for back-door, red for collider-activated — with d-separation verdict as animated text overlay)
- The change: Add a "mediator warning" step: "Identify all nodes on directed paths from treatment to outcome and print a warning: 'Do not condition on these variables — they are mediators.' Then show what happens to the identification result if the user adds a mediator to Z."
- Teardown angle: The diagram is not a picture of the analysis — it is the analysis. The rules for which paths transmit association and which don't are mechanical once you have the structure. The hard part is drawing the structure honestly, which requires substantive knowledge no algorithm can supply.
- Exclusions: Continuous structural equation estimation; latent variable modeling; time-series DAGs.
- Score: 9/10

## Candidate 03 — "Build the Back-Door Criterion Solver with Claude Code"
- Source: Causal-Inference/chapters/03-confounding-and-adjustment.md
- Lane: BUILD (Claude Code)
- Hook: "Control for potential confounders" sounds like caution. It is sometimes the exact opposite. Controlling for a collider or a mediator introduces bias that wasn't there before — and the data looks fine either way.
- The artifact: a Python script (~35 lines) that takes a DAG as an edge list and a (treatment, outcome) pair, then: (1) identifies all back-door paths from treatment to outcome, (2) checks each candidate adjustment variable against both clauses of the back-door criterion (blocks all back-door paths AND contains no descendants of treatment), (3) finds a minimal valid adjustment set if one exists, (4) flags any variable in a naive "control for everything correlated with both X and Y" that would violate the criterion — with Claude generating a one-sentence explanation of each violation — output as an animated Manim display of path-blocking.
- Prompt seed: `claude "Build a Python script using NetworkX that: (1) takes a DAG as an edge list plus treatment and outcome nodes; (2) finds all back-door paths from treatment to outcome; (3) for each candidate variable, checks: does it block all back-door paths? does it contain a descendant of treatment? (4) identifies the minimal valid adjustment set satisfying Pearl's back-door criterion; (5) calls Claude via the anthropic SDK to explain in one sentence why any variable that violates clause (b) would bias the estimate. Test on the M-bias DAG: A→X, A→M, B→M, B→Y, X→Y. Generate a Manim scene showing valid vs. invalid adjustment sets."`
- Read / check: CODE: verify M-bias DAG produces the correct result — no valid back-door path through M (M is a collider), so {A} or {B} are valid but {M} is not; verify the script does not confuse "correlates with both X and Y" (M's position) with "on a back-door path and not a descendant" (the actual criterion). OUTPUT: Manim scene should show M marked in red as invalid (opens a collider when conditioned), A marked in green as valid.
- Human supplies: Nothing — fully synthetic. Three test DAGs from the chapter (simple fork, M-bias, surgical case) cover the key scenarios.
- Output medium: Manim (animated DAG: back-door paths highlighted; valid adjustment variables turn green as they're confirmed; invalid ones turn red with annotation; the minimal adjustment set displayed as a boxed label)
- The change: Add the "all valid adjustment sets" enumeration — show that multiple valid sets often exist (e.g., {Age} OR {Severity} in the surgical case) and generate a one-sentence comparison of their relative statistical efficiency.
- Teardown angle: The back-door criterion is mechanical — once you have the DAG, the algorithm runs itself. The discipline is in having drawn the DAG honestly. And the most common expensive mistake — adjusting for everything that correlates with both treatment and outcome — is exactly what the criterion rules out.
- Exclusions: Propensity score estimation; doubly robust estimators; IV methods for cases where no valid adjustment set exists.
- Score: 9/10

## Candidate 04 — "Build a Randomization Logic Explainer with Claude Code"
- Source: Causal-Inference/chapters/04-randomization-and-its-limits.md
- Lane: BUILD (Claude Code)
- Hook: Randomization doesn't balance confounders — it deletes them from the causal diagram. That's a stronger claim than "balancing on average," and it has a precise structural meaning.
- The artifact: a Python script (~30 lines) that takes an observational DAG (as edge list) and: (1) shows the diagram with all arrows pointing into treatment (confounders), (2) simulates the RCT transformation by deleting all incoming arrows to treatment, (3) enumerates how many back-door paths existed before vs. after randomization, (4) calls Claude to generate a one-paragraph explanation of what was eliminated and what remains — with a Manim animation showing the arrows being deleted from the treatment node one by one.
- Prompt seed: `claude "Build a Python script using NetworkX that: (1) takes an observational DAG; (2) shows all nodes that have arrows pointing into the treatment node (potential confounders); (3) simulates RCT randomization by deleting all incoming edges to treatment; (4) counts back-door paths before and after; (5) calls Claude via the anthropic SDK to explain in one paragraph what the randomization eliminated and what biases could still remain (noncompliance, attrition, measurement). Generate a Manim animation of the arrows being deleted from the treatment node."`
- Read / check: CODE: verify the arrow-deletion correctly removes all edges with treatment as destination; verify the back-door path count correctly reaches zero after deletion (since no incoming arrows = no back-door paths); verify Claude's remaining-bias explanation includes at least noncompliance and loss-to-follow-up as post-randomization threats. OUTPUT: Manim animation should show each incoming arrow to treatment being "erased" sequentially, with a counter showing back-door paths dropping to zero.
- Human supplies: Nothing — fully synthetic. An observational DAG with 4-6 confounders (the chapter's blood-pressure drug example) serves as the test case.
- Output medium: Manim (animated DAG: treatment node centered; incoming arrows from confounders shown in orange; each arrow disappears one by one as if being erased; back-door path counter ticks down to zero; final scene shows the clean RCT diagram)
- The change: Add a "limits layer" — after showing the clean post-randomization diagram, add back two threats to validity: a COMPLIANCE node (imperfect compliance creates a new arrow from unmeasured motivation to actual treatment received) and an ATTRITION node (differential loss-to-follow-up creates a collider) — showing that randomization solves confounding but creates new structural problems.
- Teardown angle: Randomization is not just statistical balancing — it is a surgical intervention on the causal structure. It eliminates every arrow pointing into treatment. But it does not eliminate the possibility that the post-randomization diagram develops new arrows through noncompliance, attrition, or measurement — and those are what keep observational methods necessary even in a world that has RCTs.
- Exclusions: Intent-to-treat vs. per-protocol analysis; CONSORT reporting standards; specific trial designs (adaptive, crossover, factorial).
- Score: 9/10

## Candidate 05 — "Build a Collider Bias Simulator with Claude Code"
- Source: Causal-Inference/chapters/02-the-language-of-causal-diagrams.md (Berkson's Paradox section)
- Lane: BUILD (Claude Code)
- Hook: Two diseases are biologically independent. But inside a hospital, they appear negatively correlated — one appears protective against the other. No biology changed. The selection did the work.
- The artifact: a Python simulation script (~35 lines) that: (1) generates a synthetic population of N=10,000 individuals with two independent binary conditions (Disease A, Disease B), (2) applies a collider selection rule (anyone with either disease is "hospitalized"), (3) computes the correlation between A and B in the full population (near zero) vs. inside the hospital (negative), (4) generates a Berkson-paradox visualization showing the association appearing from nothing — plus a Claude-generated one-paragraph explanation of why this happens structurally.
- Prompt seed: `claude "Build a Python simulation of Berkson's paradox. Generate N=10,000 individuals with independent binary Disease_A (prevalence 5%) and Disease_B (prevalence 5%). Apply collider selection: hospitalized=True if Disease_A OR Disease_B is True. Compute: (1) correlation between A and B in full population, (2) correlation among hospitalized patients only. Print both. Call Claude via the anthropic SDK to explain in one paragraph why the hospital sample shows a negative correlation despite biological independence. Also generate a Manim scene showing two separate population clouds (full vs. hospital) with the correlation displayed for each."`
- Read / check: CODE: verify the correlation in the full population is near zero (independent diseases); verify the correlation in the hospitalized population is substantially negative (Berkson effect); verify the exact numbers from the chapter are reproducible (at N=10,000, hospital sample shows ~P(C|A) ≈ 4.8% vs P(C|¬A) ≈ 100%). OUTPUT: Manim scene should show two distinct population clouds — the full population with dots scattered randomly (zero correlation), and the hospital population with a visible negative trend line.
- Human supplies: Nothing — fully synthetic. The simulation generates its own data; no real patient records needed.
- Output medium: Manim (two animated scatter clouds side by side: left = full population (random), right = hospital subset (downward trend line emerging as dots are selected); correlation coefficient animating in for each)
- The change: Add a "dating pool" version: swap Disease A/B for Attractiveness/Kindness, apply the dating filter (date if attractive OR kind), and show the same negative correlation emerging in the dating pool — demonstrating the collider mechanism appears in everyday life, not just medicine.
- Teardown angle: Conditioning on a collider manufactures association that was not there. This is the exact opposite of what conditioning on a fork does — and the two operations look identical in a regression. Only the diagram tells you which is which.
- Exclusions: Formal M-bias derivation; continuous colliders; collider bias in longitudinal data.
- Score: 9/10

- Lane: BUILD (Claude Code)

(3) reports a pass/fail table with a confusion matrix showing correct vs. incorrect rung classification — output as a Manim animated report card.
- Prompt seed: `claude "Build a Python script that benchmarks an LLM's causal reasoning. For each, call Claude via the anthropic SDK. Grade the response: (1) Did Claude correctly identify the rung? (2) Did Claude hedge appropriately for Rung 2+ when no causal structure was given? - Read / check: CODE: verify the grading rubric is operationalized (not just "did Claude sound confident" but specifically "did Claude use do-operator language or potential-outcomes language for Rung 2+"); verify the 10 questions span genuinely different rungs (not all ambiguous). - Human supplies: Nothing — fully synthetic. All 10 questions are generated synthetically in the script.
- Output medium: Manim (animated report card: questions appearing one by one in a table with rung labels; pass/fail marks appearing; confusion matrix building as a heat map; overall accuracy scores flashing in at the end)
- The change: Run the same battery with explicit causal structure provided to Claude ("assume the following DAG: ...") and compare pass/fail rates — demonstrating that Claude's causal reasoning improves dramatically when structural assumptions are supplied vs. when it must infer them.
- Teardown angle: The model's failure on causal reasoning is architectural, not a data quantity problem. Next-token prediction cannot produce structural causal reasoning because the structure is not in the tokens — it is in the domain knowledge the analyst brings. The benchmark makes the failure visible rather than hidden inside fluent-sounding answers.
- Exclusions: Full evaluation across multiple LLM providers; formal benchmark comparison with GPT/Gemini; prompt engineering for improved causal reasoning.
- Score: 9/10

## Candidate 07 — "Build a Sensitivity Analysis Tool with Claude Code: How Robust Is Your Estimate?"
- Source: Causal-Inference/chapters/11-chapter-sensitivity-analysis.md
- Lane: BUILD (Claude Code)
- Hook: You've estimated a treatment effect by adjusting for observed confounders. But what if you missed one? How strong would the hidden confounder have to be to explain away your entire result?
- The artifact: a Python script (~35 lines) that implements Rosenbaum's sensitivity analysis for an observational estimate: (1) takes a point estimate (ATE) and its confidence interval, (2) sweeps over gamma (unmeasured confounding strength from 1.0 to 3.0 in 0.1 steps), (3) at each gamma, computes the sensitivity bounds on the p-value (Rosenbaum bounds), (4) identifies the gamma* at which the result is no longer significant, and (5) calls Claude to generate a one-sentence interpretation of that threshold — output as a Manim animated line showing p-value rising as gamma increases, with the significance threshold crossing marked.
- Prompt seed: `claude "Build a Python sensitivity analysis tool implementing Rosenbaum bounds. Input: ATE estimate, confidence interval, sample size n, number treated n1, p-value at gamma=1. Sweep gamma from 1.0 to 3.0 in steps of 0.1. At each gamma, compute the Rosenbaum upper bound on the p-value using the Mantel-Haenszel statistic. Plot the p-value bound as a function of gamma. Identify gamma* where p > 0.05. Call Claude via the anthropic SDK to interpret gamma* in one sentence ('an unmeasured confounder would have to increase odds of treatment by a factor of X to explain away this result'). Generate a Manim scene of the rising p-value curve with the significance threshold crossing annotated."`
- Read / check: CODE: verify the Rosenbaum bound formula is correctly implemented (consult the original 1987 paper or a standard reference implementation); verify gamma=1 recovers the original p-value exactly. OUTPUT: Manim scene should show p-value starting below 0.05, then rising through the threshold as gamma increases — with gamma* labeled as an annotation.
- Human supplies: A point estimate and confidence interval from a real or synthetic observational study. Claude cannot generate credible causal estimates from scratch — the human supplies the numbers, Claude supplies the sensitivity analysis and interpretation.
- Output medium: Manim (animated line chart: x-axis = gamma (unmeasured confounding strength), y-axis = p-value bound; line rises from left; dashed horizontal line at p=0.05; the crossing point labeled as gamma*; Claude's one-sentence interpretation displayed as animated subtitle)
- The change: Compare two estimates with the same point estimate but different gamma*: one with a fragile result (gamma* = 1.2) and one with a robust result (gamma* = 2.8) — demonstrating that two studies can agree on the estimate but disagree on how much unmeasured confounding would be needed to overturn it.
- Teardown angle: Every observational estimate is conditional on having measured all the relevant confounders. Sensitivity analysis quantifies the assumption you can't test — and makes visible whether your conclusion is robust or hanging by a thread.
- Exclusions: E-value computation (alternative sensitivity measure); Cornfield conditions; longitudinal sensitivity analysis.
- Score: 8/10

## Candidate 08 — "Build a Causal Variable Identifier with Claude Code: LLM-Assisted DAG Construction"

- Lane: BUILD (Claude Code)
- Hook: Building a DAG requires domain knowledge — which variables to include, which arrows to draw, which to leave out. But the analyst can't always enumerate every relevant variable. What if Claude could surface the candidate confounders you didn't think of?
- The artifact: a Python script (~35 lines) that takes a causal question (treatment, outcome, domain description) as text input, calls Claude to: (1) generate a candidate list of variables that might affect both treatment and outcome (candidate confounders), (2) classify each candidate as likely confounder / likely mediator / likely collider / unclear, (3) output a proposed DAG edge list based on domain reasoning — then feeds that edge list into a NetworkX DAG and runs the back-door criterion solver from Candidate 03 to check identification — output as a Manim visualization of the proposed DAG.
- Prompt seed: `claude "Build a Python script that uses Claude as a causal variable identifier. Input: (1) treatment variable name, (2) outcome variable name, (3) domain description string. Call Claude via the anthropic SDK to: (a) list 6-10 variables that might affect both treatment and outcome in this domain; (b) classify each as likely confounder/mediator/collider/unclear with one-sentence rationale; (c) propose a DAG as a list of (from, to) tuples. Then load the proposed DAG into NetworkX, run the back-door criterion, and report whether the causal effect is identified from the proposed variable set. Generate a Manim scene of the proposed DAG."`
- Read / check: CODE: verify the NetworkX back-door criterion from Candidate 03 is correctly integrated; verify Claude's proposed DAG edge list is parseable (watch for formatting errors in Claude's output). OUTPUT: test on the HRT/heart-disease example from Chapter 3 — Claude should identify health-consciousness and income as likely confounders; verify the back-door criterion identifies {health_consciousness, income} as a sufficient adjustment set.
- Human supplies: A domain description string for the causal question of interest. Claude's variable enumeration is a starting hypothesis — the human must validate which variables are actually measurable and whether the proposed causal directions match domain knowledge. This is a human-in-the-loop tool, not an autonomous DAG builder.
- Output medium: Manim (animated DAG building from Claude's proposed edge list: nodes appearing with labels, edges drawing in, color-coding by variable type — orange for confounders, blue for mediators, red for colliders; back-door identification verdict displayed as text overlay)
- The change: Show the "commitment cost" — present the same domain to two analysts who draw different DAGs, feed both through the back-door criterion, and demonstrate that the two DAGs produce different adjustment sets and potentially different causal conclusions. Claude's proposed DAG is one substantive claim; the analyst must own the choice.
- Teardown angle: Claude can enumerate candidate variables faster than an analyst can think of them. It cannot commit to an arrow. Every edge in the DAG is a substantive causal claim about how the world works — and that claim belongs to the domain expert, not the model.
- Exclusions: Automated causal discovery algorithms (PC algorithm, FCI); time-series causal discovery; graph equivalence classes.
- Score: 8/10
