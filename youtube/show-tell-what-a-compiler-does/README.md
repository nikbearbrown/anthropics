# What a Compiler Does

**What this is.** A show-tell explainer (about 3.3 minutes) of what a compiler does, stage by stage, drawn on the pipeline of Claude's C Compiler exactly as its design doc names it. A C source page rides a belt through four machines and comes out as a taped ELF box; then one stage per beat: the preprocessor pastes in headers, expands macros and drops switched-off code; the lexer cuts the text into tokens that keep their spans; the parser builds a syntax tree by recursive descent; semantic analysis types every expression, computes constants and fills the symbol table; lowering turns the tree into IR, where every local starts as a stack slot; mem2reg promotes the slots into registers in SSA form, with phi nodes where paths meet; the optimizer loops its passes up to three times (constant folding, dead code elimination), then turns phi nodes into copies; the back end picks one of four chips (x86-64, i686, AArch64, RISC-V 64) and writes assembly; a peephole pass cuts store-then-load waste; the built-in assembler encodes bytes into a .o; the built-in linker joins it with the C runtime and libraries and writes the ELF executable. It ends on the README's own warning, quoted word for word.
