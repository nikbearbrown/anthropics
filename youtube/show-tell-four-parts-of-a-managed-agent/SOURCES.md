# SOURCES — show-tell-four-parts-of-a-managed-agent

**What this is.** The primary sources for every claim, and how each one was read. **Why.** Claude Managed Agents is in beta, and the local inventory says "live public docs win", so the film checks the local file against the raw live docs. Naming Anthropic's docs and repo is fine (the bookloop law does not apply to this batch).

1. **`anthropics/launch-your-agent/cma-primitives.md`** ("Claude Managed Agents — Features & Primitives Inventory", Anthropic, Apache-2.0; its header says it is a full read of the docs on 2026-06-14 and that "live public docs win"; read in full 2026-09-27). Used: "The 4 core primitives" table (Agent / Environment / Session / Events), the Agent section (config fields, versioning), Environment (cloud or self-hosted, packages, networking, "each session gets its own fresh isolated container"), Session (create then send an event, statuses, checkpointing and resume), Events (`user.*` in, `agent.*`/`session.*` out; steering and interrupt). **Superseded by the live docs:** its "Checkpoints kept 30 days after last activity … ping with a message to reset the timer" (see 3). **Not used:** outcomes, permission policies, skills limits, memory stores, vaults, multi-agent, deployments, Dreams (research preview), rate limits, model names.
2. **`anthropics/launch-your-agent/.claude/skills/launch-your-agent/references/cma-api.md`** (read 2026-09-27) — the command shapes for create agent → environment → session → event; confirms the same four objects and `version` starting at 1. Nothing in the film depends on it alone.
3. **Live docs, raw markdown**, fetched with curl on 2026-09-27 (the `.md` source of each page, not a WebFetch summary), saved in `sources/live-docs-2026-09-27/`:
   - `https://platform.claude.com/docs/en/managed-agents/overview` — "status: beta"; "Claude Managed Agents is in beta"; the four core concepts; "Create the agent once and reference it by ID across sessions"; steer or interrupt; dreaming and MCP tunnels are a more limited research preview.
   - `…/managed-agents/agent-setup` — the agent bundles "the model, system prompt, tools, MCP servers, and skills"; "The `version` starts at 1 and increments each time an update changes the agent"; List versions returns "the full version history".
   - `…/managed-agents/environments` — "You create an environment once … Multiple sessions can share the same environment, but each session gets its own isolated sandbox (a fresh Linux container)"; "Sessions do not share filesystem state"; `packages`; networking `unrestricted` (default) / `limited` with `allowed_hosts`.
   - `…/managed-agents/sessions` — a session references an agent and an environment; `initial_events` can start it `running`.
   - `…/managed-agents/session-operations` — statuses `idle` ("Sessions created without `initial_events` start in `idle`"), `running`, `rescheduling`, `terminated`.
   - `…/managed-agents/events-and-streaming` — "Communication … is event-based"; `user.message`; `user.interrupt`; "Resuming an idle session": the checkpoint, and "sandbox state is only preserved for 30 days after the sandbox is created. Activity does not extend this window".
   - `…/managed-agents/reference` — event types `agent.message`, `agent.tool_use`, `agent.tool_result`, `session.status_running`, `session.status_idle`.
   Other live-doc drift noticed and left out of the film: an agent update's `version` is now optional (the local file says to pass it), and a session can carry a `budget` cap (the local file says there is no spend cap inside CMA).
