# The Loop That Won't Let Claude Leave

**What this is.** A show-tell explainer (about 2 minutes 22 seconds) of Anthropic's Ralph Loop plugin for Claude Code, drawn as one workshop. Claude is a kraft worker at a bench. One command, `/ralph-loop`, pins the task above the bench as the prompt and writes a small state file: the prompt, a lap counter starting at 1, the cap, and the promise phrase. Claude works, the repo shelf fills, and Claude heads for the door. There the Stop hook reads the state file and Claude's last message, drops its gate arm, adds one to the counter, and hands back the same prompt, word for word. Lap after lap the prompt stays the same while the work piles up. The loop ends on an exact promise (the hook deletes the state file and the door opens) or when the counter hits max iterations, done or not. Labels only; Liam's voice does the explaining. **Why.** Card #13 in `../show-tell-ideas.md` (Batch 2), built on Bear's overnight order of 2026-09-27: one very visual mechanism, no dedicated film yet, and students are using it now. It stands alone next to the hooks primer (#25). **Found.** Every claim matches the maintained copy, `anthropics/claude-plugins-official/plugins/ralph-loop/`: README, commands, `hooks/stop-hook.sh`, `scripts/setup-ralph-loop.sh`. The plugin's cautions are given as it states them. With neither a cap nor a promise, the loop runs forever. Always set `--max-iterations`, which the README calls the primary safety mechanism, because the promise is an exact match and can't signal "stuck". Use the loop for work a test can check, not work that needs human judgment. `/cancel-ralph` stops it early. The plugin gives no cost caution and no sourced numbers, so the film claims none.
