## Candidate 01 — Build a Value Chain Cost-Leak Finder with Claude Code
- Source: mba-case-studies/chapters/04-value-chain-analysis.md
- Lane: BUILD (Claude Code)
- Hook: A running shoe costs $15 in materials and sells for $150. Where does the other $135 go — and which stage is leaking margin it should be capturing? The value chain is the map; the math reveals the weakest link.
- The artifact: A Python script that takes a 7-stage value chain cost breakdown (as a CSV: stage, fixed_cost, variable_cost, revenue_contribution) and outputs: (1) fixed vs. variable split per stage, (2) margin contribution per stage, (3) a "weak link" flag for any stage where cost share exceeds expected industry benchmark (user-inputted), (4) a Manim bar chart animating cost and revenue contribution per stage side-by-side with weak links highlighted in red.
- Prompt seed: `claude "Write a Python script that reads a 7-row CSV (columns: stage, fixed_cost, variable_cost, revenue_contribution) representing a value chain, computes margin per stage (revenue minus total cost), identifies weak links where cost share exceeds a user-supplied industry benchmark, and outputs a summary table plus a matplotlib bar chart with weak links colored red. Use synthetic running-shoe data: Product Development 8% of costs, Sourcing 12%, Manufacturing 35%, Logistics 18%, Distribution 14%, Retail/Marketing 10%, After-Sales 3%. Revenue contribution: Manufacturing 0%, Marketing 40%, Distribution 25%, Retail 35%."`
- Read / check: Verify the margin math — margin per stage = revenue_contribution minus (fixed_cost + variable_cost), expressed as percentage of total revenue; check that the weak-link flag logic compares cost_share to the benchmark correctly; verify that the chart x-axis labels all seven stages and the bars are grouped (cost vs. revenue contribution) rather than stacked.
- Human supplies (Claude can't): A real company's actual cost breakdown per stage (the synthetic running-shoe data is illustrative; a real CFO analysis would require internal data). The synthetic dataset is explicitly acceptable for the video — state this in the intro beat.
- Output medium: Manim (bar chart animating stage by stage, weak-link bars lighting up red; margin contribution line overlaid on the bars)
- The change: Add a "what-if" slider — if the company reduces logistics cost by 20% (from 18% to 14.4%), how does the margin map change? Show the re-run with updated weak-link flags.
- Teardown angle: The value chain's "weakest link" property means fixing the strongest stage first is a mistake — the company with world-class manufacturing but catastrophic logistics will see its manufacturing advantage neutralized. The tool forces you to look at the whole chain, not just the stage you're proud of.
- Exclusions: Activity-based costing academic literature; DCF of individual stage investments; competitive intelligence (who has a better chain) — save for a strategy-level card.
- Score: 9/10

## Candidate 02 — Build an M&A Net-Benefit Calculator with Claude Code
- Source: mba-case-studies/chapters/09-mergers-and-acquisitions-framework.md
- Lane: BUILD (Claude Code)
- Hook: The largest deal in history — AOL/Time Warner, $165 billion — destroyed $99 billion in value in two years. The arithmetic was available upfront. Why didn't anyone run it honestly? This card builds the model that the deal architects didn't.
- The artifact: A Python DCF-plus-synergy M&A net-benefit calculator: inputs are standalone DCF value of target (via a simple perpetuity-growth model), synergy estimates split into cost synergies and revenue synergies with user-supplied haircut factors, acquisition premium paid, and integration costs; outputs are: (1) net benefit (haircutted synergy NPV minus premium minus integration costs), (2) deal verdict (create value / destroy value / marginal), (3) a Manim waterfall chart animating standalone value + synergies - premium - integration costs = net benefit.
- Prompt seed: `claude "Write a Python script implementing an M&A net-benefit calculator. Inputs: target standalone DCF value (entered directly, or computed from terminal EBITDA and EV/EBITDA multiple), cost synergies (annual $ and discount rate), revenue synergies (annual $ and discount rate), cost-synergy haircut (default 0.75), revenue-synergy haircut (default 0.40), acquisition premium paid, integration costs. Outputs: haircutted NPV of each synergy type, total net benefit (standalone + haircutted synergies - premium - integration), deal verdict. Use the AOL/Time Warner case as synthetic test data: standalone Time Warner value ~$83B, cost synergies $1B/yr, revenue synergies $4B/yr, premium $82B, integration costs $5B."`
- Read / check: Verify that the haircutted synergy NPV formula is correct — cost_synergy_haircut × PV(annual_cost_synergies); verify that the deal verdict logic flags net benefit < 0 as "destroys value"; check that the AOL/Time Warner test data produces a negative net benefit (which it should, given the premium dwarfed the haircutted synergies); confirm the waterfall chart labels are correct (standalone, + cost synergies, + revenue synergies, - premium, - integration = net benefit).
- Human supplies (Claude can't): A real M&A deal's actual synergy estimates and integration cost projections (the AOL/Time Warner synthetic data is explicitly an illustrative stand-in; the chapter's own analysis is the source). Real deal data would require NDA-protected client documents. Synthetic data is acceptable for the video.
- Output medium: Manim (waterfall chart: each component animates as a bar segment building left to right; bars above zero are green, below zero are red; the net-benefit final bar is the widest, colored by sign)
- The change: Apply the same calculator to the Halverson/Cardinal Systems deal from the corporate finance book — $550M standalone, haircutted synergies ~$200–270M, premium $150M over standalone, integration costs $30M — and show whether the deal verdict changes under different haircut assumptions (the "range of outcomes" sensitivity table).
- Teardown angle: Revenue synergies routinely fail to materialize because they require customer behavior changes the acquirer cannot control. The haircut asymmetry (75% for cost, 40% for revenue) is not conservative pessimism — it is the empirical record of what actually happens when you study post-acquisition performance over three-to-five years. Build the model with honest haircuts before presenting it to the board.
- Exclusions: Comparable-transactions analysis (interesting but a separate data-collection problem); precedent-transaction database access; integration management playbooks; due diligence process mechanics.
- Score: 9/10

## Candidate 03 — Build a Pricing Framework Decision Engine with Claude Code
- Source: mba-case-studies/chapters/07-pricing-framework.md
- Lane: BUILD (Claude Code)
- Hook: A bottle of water at a grocery store is worth $1. The same bottle at the end of a long hike is worth considerably more. Price is not a number attached to a product — it is the fraction of a buyer's value the seller captures. This card builds the model that helps you find that fraction.
- The artifact: A Python pricing decision engine: given four inputs (product category from a menu: new-invention / modification / similar-to-existing / portfolio-pricing; customer willingness-to-pay estimate; cost-plus floor price; competitor benchmark price), the tool outputs: (1) recommended methodology (value-based / cost-plus / competitor-based / portfolio), (2) price range with floor and ceiling, (3) a price sensitivity table showing revenue at 5 price points between floor and ceiling, (4) a Manim animated curve showing total revenue vs. price with the recommended price marked.
- Prompt seed: `claude "Write a Python pricing decision engine. Inputs: product_category (one of: new_invention, modification, similar_to_existing, portfolio), willingness_to_pay (float), cost_plus_floor (float), competitor_benchmark (float, may be None). Logic: if new_invention → use value-based methodology → recommended price = 0.7 × willingness_to_pay; if modification → recommended price = min(willingness_to_pay, competitor_benchmark × 1.15); if similar_to_existing → recommended price = competitor_benchmark × 0.95 to 1.05; if portfolio → flag for human judgment. Output: methodology name, recommended price, and a 5-row revenue sensitivity table at ±20% around recommended price assuming linear demand with elasticity=-1.5."`
- Read / check: Verify that the value-based methodology correctly uses willingness-to-pay as the ceiling and cost-plus as the floor; check that the portfolio category correctly flags for human judgment rather than producing a formula output; verify the revenue sensitivity table formula: revenue = price × quantity, where quantity = base_quantity × (price/base_price)^(-1.5); confirm the new-invention 70% WTP recommendation reflects the opportunity-cost gap logic from the chapter.
- Human supplies (Claude can't): A real customer willingness-to-pay study (the synthetic inputs are illustrative; real WTP requires conjoint analysis surveys or Van Westendorp pricing interviews). Synthetic data is explicitly acceptable for the video — state this in the intro beat. A real product launch would require primary research.
- Output medium: Manim (revenue-vs-price curve animating from left to right; recommended price marked with a vertical dashed line; floor and ceiling labeled; the revenue sensitivity table appearing below the curve)
- The change: Run the engine on a SaaS pricing problem — a $0/user/month freemium tier and a $49/user/month paid tier. Ask Claude to identify at what user ratio the portfolio pricing creates cannibalization risk and when it actually expands total addressable market.
- Teardown angle: Cost-plus pricing answers "what do we need?" not "what can we get?" A company that prices purely at cost-plus leaves money on the table whenever its value-based price is above its cost-plus floor — which, for a well-differentiated product, is almost always. The tool forces you to start from value, not cost.
- Exclusions: Conjoint analysis methodology; Van Westendorp price sensitivity meter; dynamic pricing algorithms; price discrimination across geographies.
- Score: 8/10

## Candidate 04 — Build a Porter's Five Forces Scorer with Claude Code
- Source: mba-case-studies/chapters/12-strategic-frameworks-porters-five-forces-value-chain.md
- Lane: BUILD (Claude Code)
- Hook: Porter's Five Forces is the framework that every MBA student draws and almost no one quantifies. This card turns it into a scored model — a diagnostic that tells you not just which forces are present but which ones are actually crushing your margins.
- The artifact: A Python script that takes 25 user-rated inputs (5 forces × 5 sub-factors, each scored 1–5 for intensity), computes a weighted average for each force, plots a radar/spider chart of force intensity, and outputs a "structural profitability" score with a recommended strategic priority (defend against the highest-intensity force first); delivered as a Manim animated radar chart where each force fills in as the user inputs scores, with the final chart color-coded by intensity quartile.
- Prompt seed: `claude "Write a Python Five Forces scorer. Input: a dictionary with five keys (supplier_power, buyer_power, competitive_rivalry, threat_of_substitution, threat_of_new_entry), each containing a list of five sub-factor scores (integers 1–5). Output: weighted average score for each force, an overall structural profitability score (inverted: high force intensity = low profitability), a matplotlib radar chart of the five forces, and a recommended strategic priority: whichever force has the highest score. Test with airline industry typical values: rivalry=4.5, buyer_power=4.0, supplier_power=3.5, new_entry=2.0, substitution=3.0."`
- Read / check: Verify the overall structural profitability score is correctly inverted — high average force intensity maps to low profitability score; check the radar chart produces a pentagon shape with five labeled vertices; confirm the strategic priority recommendation correctly identifies the maximum-intensity force; verify that the airline test inputs produce rivalry as the top threat (airline industry is the textbook high-rivalry case).
- Human supplies (Claude can't): Industry-specific sub-factor ratings (the airline test data is a synthetic illustrative stand-in; a real industry analysis requires company 10-K reading, analyst reports, or primary research). Synthetic data is explicitly acceptable for this video.
- Output medium: Manim (radar chart pentagon animating one spoke at a time; each spoke fills with color intensity from green at 1 to red at 5; strategic priority force flashes on completion)
- The change: Run the same scorer on two industries — airlines (high rivalry, high buyer power) and luxury goods (low substitution, low new entry threat) — and show the structural profitability score difference. Ask Claude why luxury goods firms can sustain margins that airline firms cannot, even at similar revenue scale.
- Teardown angle: Porter's Five Forces tells you whether an industry is structurally attractive. It doesn't tell you whether a specific firm within the industry is positioned to capture that attractiveness. A firm can operate in a terrible industry (airlines) and still be Southwest — or operate in a great industry (luxury goods) and still fail at positioning. The tool is industry-level, not firm-level.
- Exclusions: BCG matrix (different card); VRIO framework; SWOT matrix; value-chain application to competitive analysis (covered in Candidate 01).
- Score: 8/10

## Candidate 05 — Research the AOL/Time Warner Failure Framework with Claude
- Source: mba-case-studies/chapters/09-mergers-and-acquisitions-framework.md
- Lane: RESEARCH (Claude assistant)
- Hook: In 2000, AOL acquired Time Warner for $165 billion — the largest deal in history. By 2009, the companies had separated, with AOL worth a fraction of what Time Warner had been worth independently. The failure was not a strategic mistake. It was an analytical one. The diagnosis was available in 2000 — nobody ran it honestly.
- The artifact: A sourced four-component M&A failure analysis: (1) what the target was worth on its standalone DCF, (2) what synergies were plausible with honest haircuts, (3) what acquisition premium was actually paid, (4) what integration risks the deal architects failed to model — annotated with the specific failure of the AOL broadband-transition assumption; delivered as a Manim waterfall chart (standalone value + haircutted synergies - actual premium = projected net benefit, compared to realized outcome).
- Prompt seed: `claude "Analyze the AOL/Time Warner merger failure using the M&A net-benefit framework. Four components: (1) Time Warner standalone value in 2000 — what were analysts estimating, and what DCF inputs were plausible at the time? (2) Synergies — what cost and revenue synergies were projected, and applying empirical haircuts (75% cost realization, 40% revenue realization), what was the haircutted NPV? (3) Premium — what was the actual premium paid over Time Warner's standalone value? (4) Strategic risk — what assumption about the business environment (broadband adoption timeline) was the deal's critical failure point, and what evidence was available in 2000 that should have informed a more conservative scenario? Produce a four-section sourced analysis."`
- Read / check: Verify the $165B total deal value and the approximate Time Warner standalone value; confirm the $99B write-down figure in 2002; check that the LLM identifies the dial-up-to-broadband transition risk as the primary analytical failure (AOL's subscriber model was based on a world that was already passing); verify that the chapter's empirical finding — "acquirers underperform by negative five to fifteen percent over three to five years" — is cited.
- Human supplies (Claude can't): Nothing — fully synthetic. All AOL/Time Warner financials are public record. Verify the write-down amount and 2002 reporting year before filming.
- Output medium: Manim (side-by-side waterfall: "what the model should have shown" vs. "what actually happened"; bars animated simultaneously with labels for each component)
- The change: Apply the same four-component framework to a deal that worked — Disney/Pixar in 2006 ($7.4B). Ask Claude what the haircutted synergy NPV was, what premium Disney paid, and what integration factors (talent retention, cultural compatibility) explain why this deal succeeded where AOL/Time Warner failed.
- Teardown angle: The AOL/Time Warner failure was not a failure to understand that content and distribution are complementary. It was a failure to ask: complementary in which world? The model was correct about the strategy and wrong about the environment. Sensitivity analysis for the broadband transition timeline would have revealed the deal's exposure — but nobody built the model honestly enough to see it.
- Exclusions: Corporate governance failures post-merger; Enron accounting fraud (different failure mode); valuation of non-traded internet assets in 2000 (too historical); SPAC mechanics (different card).
- Score: 8/10

## Candidate 06 — Build a Market Entry Feasibility Screener with Claude Code
- Source: mba-case-studies/chapters/05-market-entry-framework.md
- Lane: BUILD (Claude Code)
- Hook: A company is considering entering a new market. Before doing a full strategy, it needs a 30-minute feasibility screen: Is the market big enough? Is competition intense? Is the company's capability match strong? This card builds the screener.
- The artifact: A Python market-entry feasibility screener: inputs are market size (TAM/SAM/SOM estimates), market growth rate, competitive intensity score (1–5), company capability match score (1–5), and entry cost estimate; outputs are: (1) a Go/No-Go/Further-Analysis verdict using a weighted scoring model, (2) a "critical unknowns" list for any inputs flagged as assumptions, (3) a Manim 2x2 matrix (competitive intensity vs. capability match) with the target market plotted and the four quadrants labeled (ideal entry, defend-and-differentiate, build-before-entering, avoid).
- Prompt seed: `claude "Write a Python market-entry feasibility screener. Inputs: tam_millions (float), sam_millions (float), market_growth_rate (float, annual %), competitive_intensity (int 1-5), capability_match (int 1-5), entry_cost_millions (float). Weighted scoring: market_size_score = min(5, sam_millions/100), growth_score = min(5, market_growth_rate/5), competition_score = 6 - competitive_intensity, capability_score = capability_match. Total score = 0.25 × each. Verdicts: >3.5 = Go, 2.5-3.5 = Further Analysis, <2.5 = No-Go. Output: verdict, score breakdown, and a flag for any input marked as 'estimate' by the user."`
- Read / check: Verify the weighted scoring formula produces a result on a 1–5 scale; check that competitive intensity is correctly inverted (high competition = low score); confirm the verdict threshold logic; verify that a market with $500M SAM, 15% growth, competition=3, capability=4 produces a Go verdict.
- Human supplies (Claude can't): Real market-size data (TAM/SAM/SOM figures require primary research or licensed market reports from IBISWorld, Gartner, etc.). Synthetic data is explicitly acceptable for the video. State that a real entry decision would require verified market research.
- Output medium: Manim (2x2 quadrant matrix animating; the target market plotted as a dot with a label; quadrant labels appearing one by one; the verdict appearing below the matrix)
- The change: Run the screener on three entries simultaneously — fast food chain entering India, German auto brand entering Indonesia, fintech startup entering Brazil — and show how the 2x2 matrix distributes them across quadrants with different verdicts.
- Teardown angle: The 30-minute feasibility screen is not a strategy. It tells you which questions to prioritize. A Go verdict means the fundamentals are plausible — not that the entry will succeed. A No-Go verdict means the arithmetic doesn't work before you even start on execution. Most companies skip the screen and go straight to execution planning, which is how they waste two years on markets that were never viable.
- Exclusions: BCG matrix TAM-SAM-SOM portfolio (different framework); PESTEL environmental scan; customer discovery methodology; distribution channel selection.
- Score: 7/10

## Candidate 08 — Build a BCG Matrix Portfolio Scorer with Claude Code
- Source: mba-case-studies/chapters/13-bcg-matrix-framework.md + chapters/14-bcg-matrix-tam-sam-som-portfolio-strategy.md
- Lane: BUILD (Claude Code)
- Hook: Stars, Cash Cows, Question Marks, Dogs — the BCG matrix is the most taught and least quantified framework in business school. This card builds the model that turns the 2x2 sketch into a cash-flow allocation decision.
- The artifact: A Python BCG portfolio scorer: inputs are a list of business units (name, market_share_relative, market_growth_rate, annual_free_cash_flow); outputs are: (1) BCG quadrant classification for each unit, (2) a portfolio-level cash-flow balance (do Stars + Cash Cows generate enough to fund Question Marks?), (3) a recommended capital allocation (invest/hold/harvest/divest), (4) a Manim animated bubble chart where bubble size = free cash flow, x-axis = relative market share, y-axis = market growth rate, quadrant lines at the standard 1.0 relative share and 10% growth thresholds.
- Prompt seed: `claude "Write a Python BCG matrix portfolio scorer. Input: list of dicts with keys: name, relative_market_share (float, where >1.0 = market leader), market_growth_rate (float, annual %), free_cash_flow_millions (float, may be negative). Classify each unit: Star (share>1.0, growth>10%), Cash Cow (share>1.0, growth<10%), Question Mark (share<1.0, growth>10%), Dog (share<1.0, growth<10%). Output: classification per unit, total portfolio FCF balance, recommended action per unit (invest/hold/harvest/divest), and a matplotlib bubble chart. Test with: ProductA (share=1.8, growth=15%, FCF=−20M), ProductB (share=2.5, growth=4%, FCF=80M), ProductC (share=0.4, growth=18%, FCF=−35M), ProductD (share=0.3, growth=2%, FCF=5M)."`
- Read / check: Verify the quadrant classification logic — the standard thresholds are relative market share > 1.0 (market leader) and market growth rate > 10%; check that the portfolio FCF balance correctly sums to: Cash Cow FCF - (Star investment need + Question Mark investment need); confirm ProductB is classified as Cash Cow and ProductD as Dog; verify the bubble chart axes are correctly labeled with quadrant names in each quadrant corner.
- Human supplies (Claude can't): Real business unit FCF and market share data (the synthetic test data is illustrative; real portfolio analysis requires internal management accounts). Synthetic data is explicitly acceptable for the video.
- Output medium: Manim (bubble chart animating one bubble at a time, each appearing in its quadrant; quadrant lines drawn first; bubbles sized by |FCF| with color indicating positive/negative FCF; the capital allocation table appearing below the chart)
- The change: Add a time-series dimension — run the scorer on the same portfolio with two time periods (Year 0 and Year 3 projections) and animate the bubble movements across quadrants. Ask Claude to flag any unit that moves from Star to Cash Cow (normal maturation) vs. any unit that moves from Cash Cow to Dog (margin erosion warning).
- Teardown angle: The BCG matrix tells you what to do with portfolio cash flows — but it doesn't tell you whether the market share and growth rate estimates are correct. A unit classified as a Star on optimistic projections may actually be a Dog on realistic ones. The model is only as good as the inputs, and the inputs are almost always set by the managers who want to defend their units from the "divest" recommendation.
- Exclusions: STP (segmentation, targeting, positioning) — different card; VRIO analysis — different card; GE-McKinsey nine-box (more complex, saves for advanced card); Ansoff matrix.
- Score: 8/10

- Output medium: Manim (waterfall chart animating lever by lever; current revenue bar first; each lever appears as a stacked segment; target line drawn as a horizontal dashed line; the gap labeled if levers fall short)
- The change: Run the same calculator with one lever zeroed out (new product/market = $0) — a "no new products" scenario — and show whether the remaining levers can close the gap. If not, animate the shortfall in red and ask Claude to identify which lever would need to double to compensate.
- Teardown angle: The growth framework is a budgeting discipline disguised as a strategy tool. ## Candidate 10 — Research the Due Diligence Red Flag Framework with Claude

- Lane: RESEARCH (Claude assistant)
