# Find, Prove, Fix

**What this is.** A show-tell explainer (about 2.5 minutes) of Anthropic's find-and-fix loop for securing source code, drawn as one cast: your code is a kraft building; a threat map says what counts and what is trusted; the building sits in a sealed glass sandbox with one line out, to the model API; inspectors search the roof in parallel; a finding is a crash file that trips the alarm three times out of three; a grader in a fresh box gets only the file; a judge merges duplicates on a table and ranks the rest; a patch climbs a four-rung ladder, the lessons go back to the map, and a human owns the fix. Labels only; Liam's voice does the explaining. **Why.** Card #12 in `../show-tell-ideas.md` (Batch 2), built on Bear's overnight order of 2026-09-27; a new security angle (verify by exploit) next to the published security-review film, with a different cast. **Found.** Every claim matches `anthropics/defending-code-reference-harness` (the blog post, pipeline doc, README, patching doc). Anthropic's takeaway is that finding bugs now scales and the bottleneck is proving and fixing them: by May 22, 2026 it had disclosed 1,596 vulnerabilities from its own scanning and, to its knowledge, 97 were patched. The harness's own limits are said aloud: it is a reference, not a product, built for C/C++ memory bugs; a failed proof is not proof there is no bug; its patch ladder shows the crash is gone, not that the patch is safe; a human owns every fix.
