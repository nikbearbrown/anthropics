# A Security Review on Every Pull Request

**What this is.** A 160-second show-tell explainer of `anthropics/claude-code-security-review`, drawn in the series' conveyor language: a pull request is a taped crate on a belt, Claude is a dark scanner arch over it, findings pop up as flags, a filter screen drops likely false positives, and a person, not the arch, lifts the merge gate. It has labels only, and Liam's voice does the explaining. **Why.** Card #8, the last in `../show-tell-ideas.md`; Bear said to build all the cards in order (2026-09-26). **Found.** Every claim matches the repo's README, `action.yml`, prompt, filter and comment script. It's a GitHub Action that runs on pull requests and reviews only the changed files (it may read the rest for context, but its prompt says to report only what the PR newly adds). Findings carry the line, severity, an exploit scenario and a fix. Before posting, hard rules drop low-impact kinds (denial of service, rate limits) and a second Claude pass drops findings it isn't confident in. What's left is posted as line comments in a review of type `COMMENT`, each with thumbs-up and thumbs-down reactions; nothing in the action approves or merges. The same review runs locally as Claude Code's `/security-review`, which you can copy into `.claude/commands/` and tune. The repo's own caution: it is not hardened against prompt injection, so run it only on trusted PRs and require approval for outside contributors. It never claims to find every vulnerability; its prompt says it would rather miss theoretical issues than flood you. Three overclaims from the idea card were corrected before audio (see FACTCHECK).
