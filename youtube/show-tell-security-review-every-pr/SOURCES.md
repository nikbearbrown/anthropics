# SOURCES — show-tell-security-review-every-pr

**What this is.** The primary sources for every claim, and how each one was read. All are in the local copy of `anthropics/claude-code-security-review/` (the anthropics/claude-code-security-review repository mirrored in this tree), read on 2026-09-26. Naming the repo on screen and aloud is fine (the bookloop law does not apply to this batch).

1. **`README.md`** (read in full) — "An AI-powered security review GitHub Action using Claude to analyze code changes for security vulnerabilities"; Features (AI-powered analysis, "Diff-Aware Scanning: For PRs, only analyzes changed files", PR comments, contextual understanding "beyond pattern matching", language agnostic, false positive filtering); Quick Start workflow (`on: pull_request`, `pull-requests: write`, `contents: read`, `claude-api-key: ${{ secrets.CLAUDE_API_KEY }}`); **Security Considerations** ("not hardened against prompt injection attacks and should only be used to review trusted PRs"; "Require approval for all external contributors"); inputs and outputs; the five-step Workflow; the ten vulnerability categories; the false-positive filtering list; the `/security-review` slash command and how to customize it (copy `security-review.md` into `.claude/commands/`).
2. **`action.yml`** (read in full) — composite action; inputs (`comment-pr`, `upload-results`, `exclude-directories`, `claudecode-timeout`, `claude-api-key`, `claude-model`, `run-every-commit`, `false-positive-filtering-instructions`, `custom-security-scan-instructions`); runs only on `pull_request` events; a cache marker so it runs once per PR unless `run-every-commit`; `ENABLE_CLAUDE_FILTERING: 'true'`; the comment step calls `scripts/comment-pr-findings.js`.
3. **`claudecode/prompts.py`** (read) — the audit prompt: "focus ONLY on security implications newly added by this PR. Do not comment on existing security concerns"; ">80% confident"; Phase 1 repository context research with file search tools; output fields (file, line, severity, category, description, exploit_scenario, recommendation, confidence); FINAL REMINDER "Better to miss some theoretical issues than flood the report with false positives".
4. **`claudecode/findings_filter.py`** (read) — `HardExclusionRules` (DOS/resource exhaustion, rate limiting, resource leaks, open redirect, regex injection, memory safety outside C/C++, SSRF in HTML, findings in Markdown files), then the Claude API filter per finding (`confidence_score`, `keep_finding`).
5. **`claudecode/github_action_audit.py`** (read) — fetches the PR's files and diff from the GitHub API, filters excluded directories and generated files, runs the audit, then `apply_findings_filter`, then writes the results.
6. **`claudecode/constants.py`** — default model and timeouts (not used in the film).
7. **`scripts/comment-pr-findings.js`** (read in full) — builds one review comment per finding on its `path` and `line`, posts a review with `event: 'COMMENT'`, and adds `+1` and `-1` reactions to each comment; skips if security comments already exist.
8. **`.claude/commands/security-review.md`** (read in full) — the `/security-review` command: "Complete a security review of the pending changes on the current branch"; the same objective, exclusions, categories and false-positive filtering as the Action's prompt.
9. **`docs/custom-filtering-instructions.md`**, **`docs/custom-security-scan-instructions.md`** (read in full) — the two custom-instruction inputs (tuning, not used on screen).
10. **Grepped in the tree** — no `APPROVE`, `REQUEST_CHANGES` or merge call in `scripts/`, `claudecode/` or `action.yml`.
11. **Cast and patterns reused** from the batch's earlier show-tell films (`show-tell-five-ways-to-wire-an-agent/` belts, crates, dark stations and ink gates; `show-tell-claude-plugin-portal/` conveyor and gates; `show-tell-one-plugin-per-service/` dark-kraft outlines, the midpoint guard, and the greeting re-voice script).
