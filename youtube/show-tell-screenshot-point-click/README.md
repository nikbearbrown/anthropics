# Screenshot, Point, Click

**What this is.** A show-tell explainer (about 2:41) of Claude's computer use, drawn as one cast. Claude never touches the desktop: in Anthropic's quickstart demo a whole Linux desktop runs in a Docker container, and your code sits between it and Claude. You send the task, Claude asks to see the screen, your code takes a screenshot and sends it; Claude answers with an action at an x, y spot counted in the screenshot's pixels; your code scales that spot back up to the real screen and clicks; a fresh screenshot goes back, and the loop runs until Claude answers in text. Screenshots pile up, so the docs suggest keeping the last three and pruning in batches (or, on the newest models, letting the API clear them). The last three beats are the warning, in Anthropic's own words: a dedicated VM or container with minimal privileges, no access to sensitive data such as logins, an allowlist of domains; prompt injection from what's on screen; and a human who confirms consequential actions, checked before each action because a batch can do several in one turn.
