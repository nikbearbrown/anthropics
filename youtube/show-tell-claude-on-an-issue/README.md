# @claude on an Issue

**What this is.** A show-tell explainer (about 3.4 minutes) of what actually happens when you tag `@claude` on a GitHub issue with Anthropic's Claude Code Action. An issue board holds the issue, your `@claude` comment and, later, Claude's tracking comment; a repo tray, a key safe and a dark runner sit below; a branch grows at the right. One step per beat: a repository admin sets it up once (the Claude GitHub app, the `ANTHROPIC_API_KEY` secret, `claude.yml` in the workflows folder; `/install-github-app` walks you through the app and the secret); a comment with the trigger phrase (whole word, `@claude` by default; also assignee or label triggers); the workflow's phrase check and the write-access check open the gate; the job runs "entirely on your own GitHub runner", checks out the code and gets the key; Claude posts ONE comment, "Claude Code is working", and ticks a to-do list in it; it reads the issue, comments and code, then answers or changes the code; on an issue it always makes a new `claude/` branch and pushes only there; it doesn't open the PR, it leaves a **Create PR** link you press; the docs' "cannot" list (no formal reviews, no approving "for security reasons", no merge or rebase); and its small reach (one repo, no Bash unless allowed, no writes to workflow files). Labels only; Liam's voice does the explaining. **Why.** Card #29 in `../show-tell-ideas.md` (Batch 2), built on Bear's overnight order of 2026-09-27; common in class repos. **Found.** The local copy of the repo matches the live docs on every line the film uses; the limitations are spoken as the docs word them, and no numbers are used.
