# One Plugin per Service

**What this is.** A 160-second show-tell explainer of `anthropics/claude-tag-plugins`, drawn as a wall of sockets: the team's workspace, Claude Tag (@Claude, the Claude you tag in a chat thread) as a chat bubble, and one plug per service. It has labels only, and Liam's voice does the explaining. **Why.** Card #7 in `../show-tell-ideas.md`; Bear said to build all the cards in order (2026-09-26). **Found.** Every claim matches the repo's README, marketplace.json and the troubleshoot plugin's docs. The repo lists eighteen plugins: sixteen services (Asana, BigQuery, Jira, Datadog, …) and two helpers (data visualization and troubleshoot). Each service is its own plugin, so a workspace connects exactly the services it uses. A plugin holds a manifest, a skill (how to connect, core operations), an endpoint catalog read on demand and, usually, small scripts, but no key: the runtime injects the credentials. Settings layer org → workspace → channel, and plugins add up along that chain: a channel can add but never remove, so what you plug in at the top reaches every channel. For GitHub, the repo's best practice is a read-only profile everywhere and a write profile only where Claude may push or merge, which limits the blast radius. The data-viz helper turns a table into a PNG, SVG or interactive HTML chart; the troubleshoot helper's debug-plugins checks, from inside a fresh session, what loaded, what failed and why.
