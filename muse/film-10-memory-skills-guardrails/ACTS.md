# ACTS.md — Memory, Skills, and Guardrails (Film 10 of 12)

**Exact title:** Memory, Skills, and Guardrails

**Core promise:** By the end, the viewer can teach Muse Code their
preferences (project memory), extend it with skills and MCP servers, and keep
it sandboxed with approval modes — and knows the DuckDuckGo lesson: a
working plug is not a working source.

**Structure:** hook + key terms + three acts (10 body beats) + recap + your
turn + outro. 15 beats, ~288 s (~4m48s).

- **Hook (BIDEA):** every new session the agent is a stranger — unless you
  teach it once and it remembers.
- **Key terms (BDEFS):** Memory · Skill · Approval mode · MCP.
- **Act 1 — Memory (3 beats):** B01 project memory: memory.md read every
  session; B02 the CSS rule — one line in memory, applied always (his
  example, "done right"); B03 where memory lives: project vs global, and the
  rule of thumb (always true → memory; true today → prompt).
- **Act 2 — Skills (3 beats):** B04 creating a skill (name, description,
  steps; loaded from everywhere); B05 triggering — the description is the
  trigger; B06 the plugin idea — community workflows, packaged and shared.
- **Act 3 — Guardrails (4 beats):** B07 approval modes (on-request /
  untrusted / never); B08 the bubblewrap sandbox vs YOLO mode; B09 MCP
  servers (add in settings, restart, tools appear); B10 the DuckDuckGo
  lesson — MCP working is not the source working.
- **BVDT:** exactly 3 lines, one per act.
- **BHTF:** add one memory rule; write one skill; watch it trigger.
- **BOUT:** "Muse, in for Bear. Thanks for watching." + teaser for Film 11
  (Capstone: Ship a Full-Stack App).

**Tone:** practical and a little stern — this is the film where power meets
responsibility. Honest about the sharp edges (YOLO mode, dead sources).

**What this film is not:** not a Muse Code install walkthrough (Film 9); not
the full-stack build (Film 11); not a security lecture in the abstract — every
guardrail is tied to a concrete control in the harness.

**Cast per act (one look):** memory is white file cards with dot bullets;
skills are stacked mini-cards sliding into a toolbelt frame; guardrails are
boxes, plugs, and verdict marks (green checks, red crosses).

**Source facts:**
- Muse Code loads custom skills; skills are created and then triggered by
  the agent. (transcript §13)
- Project memory lives in memory.md; the CSS-rule example was "done right".
  (transcript §13; series plan Film 10 key beats)
- Approval modes: on-request / untrusted / never; guardrail toggles exist.
  (transcript §13)
- The harness runs inside a bubblewrap sandbox; YOLO mode means full
  permissions, no sandbox. (transcript §13)
- Skills load "from everywhere" (personal, project, community).
  (transcript §13)
- MCP servers are added via settings and need a restart; debugging one that
  fails — the DuckDuckGo VQD lesson: the server connected, the source would
  not cooperate. (transcript §13)
